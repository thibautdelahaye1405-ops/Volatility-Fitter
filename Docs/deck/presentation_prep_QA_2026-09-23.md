## Read this first — findings that change what you demo

1. **SPX on Massive was broken by a one-line spelling bug — FIXED the same day (commit `4e5f8a9`, 2026-09-23a)** (§1). `MassiveProvider._underlying` sends `I:SPX` to the contracts reference, which returns 0 rows while the bare `SPX` returns rows; the key IS entitled to SPX contracts and NBBO. The fix (`_contracts_underlying`: the bare root on the contracts reference, `I:` kept for the snapshot) is live-verified: 53 expiries, 312 quotes / 298 two-sided NBBO on one expiry in 0.30 s. SPX also works on **Cboe** (30,470 contracts, SPX + SPXW, AM/PM settlement by root, 1.2 s) or Yahoo, and SPY / NVDA on Massive.
2. **0DTE needs the intraday clock switched on** (§2). `intradayClock` is OFF by default; with defaults a same-day rung has t = 0 and the fit raises "Residuals are not finite". With the clock on, SPY (2026-09-22) and NVDA (2026-09-18) 0DTE rungs fit finite in 30–50 ms at 10:00 / 12:30 / 14:30 / 15:45 ET, calendar-clean. Second caveat: the **Massive provider never lists a same-day expiry** — show 0DTE from the Series lens, a captured store, or the Cboe / Bloomberg sources live.
3. **The running app carries stale state** (§9 pre-flight): priors dated 2026-06-18 (97 days old), `Prior persistence = Off`, `Observation filter = off`, the operator pinned to `precision_messages`, `SSR custom 1.5`, a graph relation config with SX5E / DAX / SIE rows from a Bloomberg day, and Cboe red for SPY from a stale transport error (the CDN answers 200). The nine pre-flight steps in §9 fix all of it the night before.
4. **"Dividends are an input, borrow is a read, the forward is the fit"** (§4, §5). The parity regression fits F and D per expiry on mids; the discount is held through the American de-bias. Default `rate = 0` disables the escrowed (discrete-dividend) de-Am tree and makes the Borrow column read −(r + div): set a rate on the dividend-demo name. `jointCarry` is API-only.
5. **Speed** (§3): Measured today on real SPY NBBO (i7-12700H laptop with the desk app running): one node after the fetch is about 50 ms (forward 4.5 ms, quote prep with the 192-step de-Am 17 ms, LQD-24 fit 24 ms, SVI-JW overlay +3.6 ms); a 9-rung SPY chain is 0.35 s of prep + 0.34 s of LQD-24 fits, calendar ON or OFF identical because the symmetric screen found nothing to repair; the Local Vol surface 2.8 s cold / 0.9 s warm-started (5.1 bp on the converged reprice); the whole Calibrate button for the ticker 3.3 s serial. The fetch dominates a single-node refresh: 1.2–1.4 s for a live Massive ladder, 0.8 s for the whole chain on Cboe, 12.7 s for an as-of NBBO history frame. The 8-worker pool parallelises tickers, not one ticker.
6. **The active Kalman filter is for daily cadence only** (§7, §9 beat 7). It is validated >30 DTE at daily steps; on sub-day series it diverges (2026-09-10/11 finding, 1.6 → 1,033 s per frame). Use `Overlay` intraday and the `+ prior + filter` lane only on a daily-step series.
7. **A spot-vol regime is a read-time view, never a re-parametrization** (§6). Fitted parameters are byte-intact; the curve slides by R·h in total variance, so only sticky-strike (R = 1) is literally a strike shift; the LV regimes are a Hagan map or a Dupire reprice.
8. **The graph never interpolates local variance** (§9 beat 8).
9. **The Massive live stream has never actually served a quote in the running app** (§10). Massive caps the options quotes channel at about 1,000 contracts per connection and refuses an over-cap subscribe frame in full; the app subscribes every contract of every selected expiry in one frame (SPY 10,560, NVDA 1,866) and drops the error status silently, so the pill says "stream warming" forever while the SSE stays `ready: false`. Beat 5's live ticks need the subscription windowed to the fitter's strike range (≤ 950 contracts, chunked frames, error parsing) or the scenario dial. Fetch-side, the largest interactive wins are a store-first as-of lookup (12.7 s → ms on any repeat), retry/backoff on Massive instead of a session-wide gate, and Bloomberg quotes from the subscription book instead of a metered 5–16 s `bdp`. It solves in the three ATM handles; the Local Vol lens's `Graph-extrapolated` button projects the inferred smiles onto an LV sheet that is arbitrage-free by construction and labelled as a projection.

## 1. Market data

**Q: What are the tickers on Cboe and Nasdaq? Which universes/roots does each cover, and how does the app enumerate them?**

Neither exchange source has a catalogue. Both are `ExchangeChainProvider` instances over a venue adapter (`backend/volfit/data/exchange.py`); `list_tickers()` is just the app's watchlist, and *any* symbol the user types is tried on demand with one HTTP round-trip per ticker. The venue answers or refuses:

| | Cboe (`volfit/data/cboe.py`) | Nasdaq (`volfit/data/nasdaq.py`) |
|---|---|---|
| Book | Cboe's OWN book (within a tick of NBBO on liquid names) | OPRA-consolidated |
| Coverage | every US-listed equity/ETF class + the Cboe cash indices: SPX + SPXW (one `_SPX` file), XSP/XSPW, VIX/VIXW, RUT/RUTW, NDX/NDXP, DJX, OEX/XEO, ... (`roots.py:17-22` `INDEX_ROOTS`) | every US-listed equity/ETF class + the Nasdaq indices (NDX/NDXP); **not** SPX/VIX/RUT (Cboe-proprietary) |
| Endpoint | `cdn.cboe.com/api/global/delayed_quotes/options/{SYM}.json`; indices addressed `_SPX` | `api.nasdaq.com/api/quote/{SYM}/option-chain?assetclass=stocks|etf|index&limit=0` — the class is not known a priori, so the adapter tries stocks -> etf -> index and caches the hit (`nasdaq.py:38, 175-192`) |
| Symbol mapping | `cdn_symbol()`: `SPX` / `^SPX` / `SPX Index` / `SPXW` -> `_SPX`; the OCC root per expiry drives settlement (SPX AM, SPXW PM) (`cboe.py:45-56, 88-90`) | bare symbol, `^` stripped |
| Unknown symbol | CDN 403 -> "Cboe lists no options for X": a yellow per-ticker pill, `/universe.errors`; the source stays amber (`exchange.py:180-195`) | `rCode 400` on every class -> "Nasdaq lists no options for X" |
| Delay / stamp | ~15 min; the file's own `timestamp` (UTC) is the data age | ~15 min; no stamp served -> `now - 15 min` |
| Size | SPY 5.5 MB / 12.4k contracts (0.5 s); SPX 13.5 MB / 30.5k contracts (1.2 s) | SPY 2.7 MB / 6k strike rows (~1.5 s), flaky timeouts |
| Cache / quota | no key, no quota; raw chain cached 60 s per ticker, 120 s download budget, status probe cached 60 s (`exchange.py:39-45`) | same |

Auto-pick order at start: Bloomberg -> Cboe -> Nasdaq -> ASX -> HKEX -> SGX -> Eurex -> Yahoo -> Massive -> Synthetic (`serve.py:37`); a ticker can be pinned to any registered source (`state_sources.py`).

Frontend: `useUniverse.ts` debounces 300 ms (`:27, :64-90`) and `UniverseManager.tsx:105-135` renders the anchored dropdown with an "in <source>" selector — a name added from another catalogue is pinned to that source. Every source answers something, but three tiers exist:

| Source | Search tier | What you get |
|---|---|---|

| Bloomberg | **real** — `//blp/instruments` `instrumentListRequest`, equities + indices interleaved (`bloomberg_search.py`, `bloomberg.py:363-383`) | "Nvidia" -> NVDA US Equity; "SX5E" -> SX5E Index (needs the Terminal; today gated "workflow review needed") |

| File | alias search over the loaded bundle (SPX <-> SPXW), no echo (`file.py:169-187`) | `SPXW · file (SPX weeklies)` |

**Q: Massive throttle, NBBO cap, streaming constraints, per-node quote limits, API-call limits?**

*REST concurrency and backoff (all in code, none user-configurable):*
- Live snapshot: paginated 250 per page (`_SNAPSHOT_LIMIT`), one query per selected expiry, **2 expiries in flight** (`_SNAPSHOT_WORKERS = 2`, `massive.py:54-62`: measured on SPY, 3-4 workers ran slower than serial and 8 hit read-timeouts on the delayed tier). Pooled keep-alive httpx client, 15 s timeout. No cap on quotes: SPY's ~13k contracts all come back.
- Historical NBBO (`massive_history.py:37-40`): **`NBBO_CONCURRENCY = 12`** requests in flight, **`NBBO_MAX_CONTRACTS = 1500`**, ~100 ms per call -> ~12 s worst case per ticker. There is **no retry/backoff**: a `NOT_AUTHORIZED` on the probe contract or a rate-limit `ERROR` body ("exceeded the maximum requests...") on any call gates the path **for the session** (`_quote_le`, `massive.py:966-973`; `_hist_nbbo_gate`), the pool is cancelled and the chain falls back to marks (flat-file day/minute bars, else per-contract minute aggregates). Restart to retry; `VOLFIT_MASSIVE_HIST_NBBO=0` pins marks.
- Today-intraday aggregates fallback: `_INTRADAY_AGG_MAX = 1500` **raises** ("narrow the expiry selection") instead of truncating (`massive.py:872-876`); 12 in flight.

*What the 1,500 bounds:* one `fetch_chain(ticker, chosen_expiries, as_of)` call, i.e. **one ticker's whole as-of fetch across its selected expiries, calls + puts** (`state.py:791-793` passes the ticker's selected expiries; the series harvest passes the pinned rungs). It applies only to eod / past-intraday modes on Massive; live Massive, Cboe, Nasdaq, Yahoo and Bloomberg are uncapped, so a live node can be far bigger (SPX on Cboe: 1,030 quotes for two expiries, 30k for the whole 58-expiry ladder). Above the cap, `budget_contracts` keeps the nearest-the-money first ranked by |ln(K/S)|/sqrt(T) (T >= 1 day), so every expiry keeps its belly and long expiries a wider one; spot for the ranking = the underlying NBBO mid, else its minute bar, else the nearest expiry's median strike (`massive_history.py:52-77`; locked by `test_massive_nbbo_history.py:195-219`). Ten selected expiries on SPX -> ~150 contracts (~75 strikes) per smile. Progress reads "312 / 1500 contracts" in the status bar.

*WebSocket streaming (`massive_ws.py`):* one background socket per provider; auth then **one subscribe frame listing every contract** (`Q.O:...` per contract, no wildcard, no chunking — `massive_ws.py:242-250`) for the selected expiries of every ticker on Massive (`state_sources.py:95-145`, edits are incremental subscribe/unsubscribe). No cap on subscriptions in code; the vendor's per-key limits (one concurrent connection per cluster is Massive's documented rule — **unverified here**) are not guarded. Clusters: the `VOLFIT_MASSIVE_WS_URL` override (set locally to a **delayed.\*** cluster), else `wss://socket.massive.com/options`, with `wss://delayed.polygon.io/options` appended as auto-fallback; a cluster that auths but stays silent for 6 s is skipped (`massive.py:453-482`). Reconnect with capped exponential backoff 1 -> 30 s, ping every 20 s, unlimited frame size (`massive_ws.py:206-232, 314`). Message rate is not throttled: the book keeps the last tick per contract and consumers poll it (table stream 1 Hz, book-spot 5 s, stream refit every `streamRefitSeconds`).

*API-call limits:* the app **neither counts nor guards** calls. It only reacts to `NOT_AUTHORIZED` / `ERROR` bodies. Massive's public pricing (unverified here) is 5 calls/min on the free tier and "unlimited" on every paid tier; ROADMAP.md:9570 records "Options-Advanced = no rate limit" from the backtest capture (~1,500 REST quote calls per ticker-day at 12 in flight). Standing cost of the status light: `feed_status` = 2 GETs per probe, re-probed every 30 s while the selector polls (`datasource.py:46`, `massive.py:202-243`). A live fetch = ceil(contracts/250) pages per selected expiry; an as-of fetch = up to 1,501 quote calls + 1-2 spot calls.

## 2. 0DTE calibration

**Is the fit working on 0-day options, and decaying throughout the day? Tested on SPY (Tue 2026-09-22, daily expiry) and NVDA (Fri 2026-09-18, weekly expiry) at 10:00 / 12:30 / 14:30 / 15:45 ET, as-of NBBO through Massive, LQD, default options + the intraday clock.**

Short answer: yes for the engine, with two caveats a live demo must respect. (1) The sub-day clock is an **opt-in** (`intradayClock`, OFF by default): with the default options a same-day rung has t = 0 and the LQD fit raises (`ValueError: Residuals are not finite in the initial point`) — verified on all 8 instants. (2) On the **Massive source the app never lists a same-day expiry**, neither live today nor as-of a past day; the 0DTE rung is reachable on the exchange/Bloomberg sources live, on captured stores, and on the Series lens.

### Mechanism (where in code)

- **Clock.** `OptionsSettings.intradayClock` (`backend/volfit/api/schemas.py:372`, default `False`; knobs `sessionVarShare` :379 = 6.5/24, `nonTradingWeight` :386 = 1.0). `service.node_clock` (`backend/volfit/api/service.py:289-313`) values every node from the chain **snapshot timestamp** (never the wall clock) to the expiry's **settlement instant**, exact ACT/365 (`data/expiry_time.py:197-203`), clamped at 0 past settlement; the variance clock τ is the session-weighted day integral `intraday_variance_days` (`calib/intraday_time.py:96-122`), which `variance_time` (:316-339) feeds to the event clock as `base_days`. With the default share 6.5/24 the in-session density is flat, so τ = t exactly and the clock nests the legacy integer-day convention; the "research" values (share 0.6-0.9, weekend weight 0) make it "remaining trading minutes" (`Docs/notes/11_event_variance_clock.tex:225-262`). The observation filter's Δt has its own `filterClock` switch on the same integrator (`api/observation_filter.py:236-238`).
- **Settlement instant.** `default_settlement` (`data/expiry_time.py:173-194`): PM roots settle at the session close (16:00 ET, 13:00 on half-days, NYSE holidays computed from rules); AM roots `SPX/NDX/RUT` (:46) settle at 09:30 with last trade 16:15 the prior session. Chains carry a per-expiry settlement map from the provider (`data/massive.py:99-103`, store schema v7). ### What "decaying through the day" means here

Prices fix the ATM total variance w = σ²τ; the clock decides how it is quoted. Under the intraday clock τ shrinks continuously toward the settlement instant, and the fitted w shrinks with it (SPY 1.26e-5 → 1.3e-6 over the day), which is the decay. LQD parameters live in variance units: the logistic base scale is s = √(3w)/π, so L = R = log s drift toward −∞ logarithmically while the Legendre shape coefficients stay O(1) — nothing in θ blows up as τ → 0, and the warm 0DTE refit stays at 12-13 ms (perf rails `warm_slice_0dte`, budget 150 ms). What does move is the *quoted* σ: with the default flat in-session profile the last 15 minutes count as 15/1440 of a day, so the close's variance concentration reads as σ rising into the close (SPY 11.3 → 21.1 %, NVDA 40 → 107 %). The research share (0.6, weekend 0) rescales every in-session σ by a constant 0.672 (τ 0.0104 → 0.0231 d at 15:45), i.e. it fixes the level, not the U-shape — the open/close seasonality is a documented follow-up, not a knob. Intraday, the observation filter (Note 15, `filterClock` session share 0.60 / non-trading 0 at q = 90 bp/√day) was calibrated on this campaign: ATM moves 19.5 bp per 30 min, 55 bp overnight, 55 bp per weekend. The Series lens is the intraday tool: it switches the clock on for sub-day series and fits frames as they land; recorded finding 2026-09-10: the ACTIVE filter's MAP block is unusable at intraday cadence on short rungs (NaN fits, minutes per frame — a 300 s frame budget bounds it), so use the OVERLAY filter lane.

Where the time goes. One node after the fetch is ~50 ms and is split evenly between preparing quotes (de-Am + inversions, 17 ms; the forward's de-bias, 4.5 ms) and the LQD solve (24 ms, 16 evaluations of a 25-parameter trust-region step with an analytic Jacobian); the SVI overlay is noise on top. A chain is ~0.7 s of parametric work, of which the de-Am de-bias inside the forwards (190 CRR batches, ~180 ms) is the biggest single line, then 2.8 s of LV: `wall_ms_optimizer_outer` 2,180 ms (the Numba Dupire sensitivity marches inside the GN iterations) + 354 ms of residual assembly. The calendar constraint costs nothing measurable on a clean real ladder because the symmetric solver only repairs identified violations. The pool does NOT accelerate a single ticker's Calibrate (items inside a ticker group run in order; the pool parallelizes across tickers) and the `/fit/surface` fan-out gains are eaten by the per-slice payload assembly (9 smile payloads ≈ 240 ms) — the fan-out pays off for SVI (408 → 280 ms) and not for LQD (581 → 508 ms).

How the app reaches these numbers: the LQD fit batches its Jacobian (2-D cumulative Simpson + Hermite row evaluation), caches the parameter-independent quadrature grid and Legendre basis, optimizes on a 2,001-node grid and rebuilds the 8,001-node slice once at the end (`calibration-perf.md`: order-16 slice 96 → 35 → 13.5 ms across two arcs); the Black inversion is a vectorized safeguarded Newton with the analytic vega; de-Americanization is a Numba `prange` CRR kernel (192 steps, 24 bisections, up-factor powers hoisted) — ~60× the scalar path, 0.07 ms per quote here (`deam-perf-stages.md`, `Docs/deamericanization_calibration_speed_note.md` stages 1–4), with the prepared quotes keyed on a content digest so fit-setting changes never re-run it; the forward's de-Am de-bias is a fixed point on the same kernel (`data/forwards._refine_american`). Local Vol marches the forward Dupire PDE with a Numba vectorized-Thomas kernel, BDF2 on a time grid graded from the payoff kink and a per-expiry graded strike lattice (`lv-operator-arc.md`: SPY dailies 1,655 → 359 nodes, 14 → 3 s), a matrix-free Gauss-Newton that avoids trf's dense SVD and, since 2026-09-09, an active-set step for the band targets (`lv-gn-active-set-step.md`), sparse-variance value-only reprices for the three post-fit marches, an early-stop on cost stall and a parametric (LQD-Dupire) cold seed; the process pool (`api/fit_pool.py`, default cpu-1 capped at 8, spawn context, byte-identical to inline) ships each slice/LV task to a worker so multi-ticker universes scale across cores (`Docs/localvol_calibration_perf_note.md` §3 for the two LV regimes).

## 4. Dividends

**Are dividends auto-fitted when the forward is calibrated for parity, or is it only a borrow rate? If dividends are fitted, continuous or discrete, proportional or absolute (cash)?**

**Crisp answer.** Dividends are *not* fitted. The parity regression fits, per expiry and independently, exactly two numbers — the forward $F$ and the discount $D$ of the line $C-P=D(F-K)$ — and whatever carry the market prices (rate, dividends, borrow) is absorbed into $F$ as one lump. The only decomposition is a *diagnostic* borrow $b=\ln(F_{\text{theo}}/F_{\text{parity}})/T$, read against an exogenous, desk-owned dividend model (`MarketSettings`: a flat rate plus one of four dividend modes; default = continuous yield $q=0$, $r=0$). A discrete schedule enters only where the user types one or the Bloomberg seed imports one; it then sets the theoretical forward, the ex-date timing of the de-Americanization tree (escrowed cash, amounts $\alpha$-scaled to the resolved forward) and the joint borrow solve. Proportional vs absolute is a *mode choice* (`discrete_absolute` / `discrete_proportional` / `mixed`), never a calibration output.

### (1) What the parity regression solves

- **Unknowns:** $F$ and $D$ per expiry, each expiry alone — no joint fit across expiries, no term-structure prior (deliberate: maturity specials stay isolated; carry_solve.py docstring "per-expiry independence"). OLS of $y=C_{\text{mid}}-P_{\text{mid}}$ on $K$: $a=DF$, $b=-D\Rightarrow D=-b,\ F=a/D$ (`forwards.py:5-13, 208-212`; Note 06 eq. `regress`).
- **Quotes:** same-strike call/put pairs with a usable mid on both sides, at least 3 pairs (`forwards.py:105, 425-447`). Robustness: MAD trim loop (4 robust $\sigma$, floor 1 bp of spot, at most 3 rounds, `:108-112, 469-479`); discount clamped to the rate band $[-5\%,30\%]$ with $F$ re-derived from the ATM/spread-weighted price *level* $K+(C-P)/D$ when the clamp bites (`:122, 386-400, 490-500`); IV-synthesized zero-carry chains pinned to $F=S$, $D=1$ (`:454`).
- **American chains — de-bias the forward, HOLD the discount.** Parity is an equality only for European prices; raw American $C-P$ carries the call/put EEP difference (about 40 bp of forward bias, an ATM kink). `_refine_american` (`forwards.py:215-368`) de-Americanizes the near-ATM band at the candidate carry $(r,\ q=r-\ln(F/S)/T)$, reprices European, and re-implies $F$ at the *fixed* slope $-D$ (`:299`) to a fixed point. $D$ stays at raw parity because the slope is the worst-identified parameter: re-implying it drifted to absurd rates on short/dividend chains and shifts the whole IV level through the $1/(DF)$ normalization (memory gotcha 4; Note 06 invariant 3, "the two corrections never fight over the same parameter"). One gated exception (2026-07-11): when the de-Americanized call/put IV gap read *at* the forward (1 % log-moneyness kernel) exceeds 5 vol bp, the rate is bisected inside the band until the sides join (`:150-163, 324-368`, the SPY Jun-27 case); clean and short-dated chains keep $D$ bit-for-bit.
- **Held fixed:** nothing about dividends enters the regression. $F$ is a lump of rate + dividends + borrow.

### (2) The dividend data model

- Per-ticker `MarketSettings` (`schemas_market.py:33-48`), defaults when never set (`state.py:1394-1397`): see the table. Formulas (`dividends.py:11-17, 86-133`), with $\tau_i$ the ex-date year fraction and only $0<\tau_i\le T$ counting:
  - `continuous`: $F=S\,e^{(r-q)T}$
  - `discrete_absolute` (escrowed cash): $F=(S-\sum_i D_i e^{-r\tau_i})\,e^{rT}$
  - `discrete_proportional`: $F=S\,e^{rT}\prod_i(1-d_i)$, $d_i\in[0,1)$ a fraction of spot
  - `mixed`: cash for $\tau_i\le$ `switchYears`, proportional ($D_i/S$ of the prevailing spot) beyond
  - `equivalent_yield` maps any mode back to $q=r-\ln(F/S)/T$ (`dividends.py:188`), the $(r,q)$ interface everything downstream consumes.
- **Sources.** Bloomberg only: `dividend_schedule()` reads `DVD_HIST_ALL` (income rows; future-declared ex-dates, else the trailing cadence projected across the option horizon; `bloomberg.py:668-706`, `bloomberg_parse.py:263-287`) and `serve._seed_bloomberg_dividends` writes it into `MarketSettings` as `discrete_absolute` at startup (`serve.py:250-278`). Yahoo, Massive, Cboe and flat files carry **no dividend fields**. Otherwise the schedule is typed in the Forwards lens: `DividendEditor` (Cont / Cash / Prop / Mixed picker, ex-date + amount rows, switch horizon), click-to-add on the forward curve chart with an amount slider, applied by `PUT /settings/market/{ticker}`.
- **Default:** continuous, $q=0$, $r=0$ — the theoretical forward is spot and, on a non-Bloomberg source, nothing about dividends is known unless the user enters it.

### (3) Dividends inside the de-Am tree and the European reprice

- The CRR tree accepts a continuous $q$ *or* a discrete cash schedule priced by the escrowed-spot (Hull) method: the recombining lattice diffuses on $S-\mathrm{PV}_0$, the actual spot at step $n$ is lattice $+$ PV of the dividends still ahead, exercise is tested against that cum-dividend spot (`core/american.py:61-89 _escrow`; Note 05, eq. `alpha`, lines 264-282).
- `forward_consistent_cash_schedule` (`dividends.py:141-185`): ex-dates from the model, amounts scaled by
  $$\alpha=\frac{S-F\,e^{-rT}}{\sum_i D_i e^{-r\tau_i}}$$
  so the escrowed forward $(S-\mathrm{PV})e^{rT}$ reproduces the **resolved** forward exactly — timing is the forecast, amounts bend to the market. $r$ is the **physical** `MarketSettings.rate`, not the parity discount: the parity $D$ can be too low to admit positive dividends. Requirements: mode in {`discrete_absolute`, `mixed`} with a cash leg inside $(0,T]$ and $0<\alpha\le 5$; otherwise `None` and the tree falls back to the lumped continuous carry $r=-\ln D/T$, $q=r-\ln(F/S)/T$ (`quotes.py:213-219`). With the default `rate = 0` the schedule is rejected ($\alpha\le0$; numeric check below), so discrete de-Am is effectively opt-in on a *set* rate.
- Wiring: `service.prepared_quotes` resolves the forward, builds the schedule (`state.py:1480-1501`) and calls `prepare_quotes(..., cash_dividends)` (`service.py:414-421`). The de-Americanized $\sigma$ is repriced European by normalized Black at $(F,D)$: $C=DF\,c(k,\sigma^2T)$, $P=DF\,(c-1+e^k)$ (`quotes.py:224-230`); the IV round-trips to the de-Am sigma whatever $D$ normalizes, so only the ex-date EEP asymmetry is corrected and the IV level is untouched.
- Golden: flat-vol American chain with a \$2 cash dividend three months out — continuous-$q$ de-Am leaves a 62 vol-bp ATM kink, discrete de-Am brings it to 1.5 bp and recovers the flat 20 % smile (`tests/test_discrete_deam.py`).

### (4) The joint borrow / de-Am fixed point (R2 item 11)

- `carry_solve.joint_borrow` (`carry_solve.py:164-262`; Note 06 eq. `carry_fixed_point`): $b_0=0$; de-Americanize the paired mids at $(r,\ q=\text{yield}+b_i,\ \text{cash schedule})$; reprice European on the same tree and regress parity $\to F_{\text{parity}}(b_i)$; $F_{\text{theo}}(b_i)=(S-\mathrm{PV})\,e^{(r-\text{yield}-b_i)T}$; $g=\ln(F_{\text{theo}}/F_{\text{parity}})/T$, $b\leftarrow b+g$ until $|g|<10^{-5}$ (0.1 bp), at most 8 iterations, $|b|\le 200\%$ cap, at least 6 pairs. The **same** schedule rides both legs (the "discrete dividends consistent" clause); proportional modes are unsupported and return `None` (`dividend_legs`, `:105-123`); European chains short-circuit in one exact step.
- **Gate.** Measurement is always available (`GET /carry/{ticker}?joint=true`). Feeding fits is opt-in: `OptionsSettings.jointCarry` (default `False`) + `jointCarryEngageBp` (25 bp); `resolved_forward` returns the joint $(F,D)$ with source `"joint"` only when converged **and** $|b|\ge$ gate, else the parity object exactly — ordinary names byte-identical with the toggle on (`state.py:1569-1577`, `schemas.py:346-354`).
- **Sensitivity and confidence.** $\partial\sigma/\partial b=\sqrt{T}\,N(d_1)/\varphi(d_1)\approx125\sqrt{T}$ vol bp per 100 bp of borrow at fixed strike and price (`iv_borrow_sensitivity_bp`, `:77-102`); noise floor $\sigma_b\approx\text{rms}/(T\sqrt{n})$ (`borrow_noise_floor_bp`, `:63-74`).
- **Identifiability (CarryCurve v0, `api/carry.py:37-66`).** Borrow is reported only when a real parity regression stands (not zero-carry, at least 6 pairs, rms $\le 10^{-3}$ spot); otherwise `borrowBp = None`, `borrowSource = "unidentified"` — never a silent zero. Every component carries a source tag: `rateSource` desk, `dividendSource` desk | none, forward `parity_implied` | `model` | `desk` | `joint_deam`.
- **HTB verdict (2026-07-17, real GME / TTAN / WGS / UAA / PLAY capture):** the identifiability floor is right (1–3 DTE reads swing thousands of bp, skipped); GME and TTAN stable; WGS consistently negative — a flat desk rate biases borrow one-for-one, so a **term-matched rate curve** is the open dependency.

### (5) What the user sees and the settings

Forwards lens: the ladder `Expiry · T · Parity · Theo · Manual · Active · Borrow` (bp, tooltip = $1\sigma$ floor) `· [Joint · ±σ] · Source`, the "Joint carry" checkbox, the amber zero-carry badge (`ForwardsViewer.tsx:131-134, 172-173, 198-223`); the `ForwardPanel` per-expiry mode Parity / Theo / Manual plus the "Carry r / div q" row and the `DividendEditor`; Term view ex-date markers under the discrete/mixed modes (`test_api_term_dividends.py`). ### (6) So, precisely

The fitted object is the **forward** (with a held discount) per expiry; on top of an *exogenous* dividend schedule the only inferred carry component is the **borrow**, and even that is a read (or, opt-in, a joint solve), not a calibration of dividends. Dividends are **absolute** under `discrete_absolute` and the near leg of `mixed`, **proportional** under `discrete_proportional` and the far leg of `mixed`, **a yield** under `continuous`. With no schedule (Yahoo / Massive / Cboe, any ticker) the model is continuous with $q=0$: the parity forward still absorbs the market's dividend expectation implicitly (so the fits are right), the theoretical forward is bare spot growth, the "Borrow" column reads dividend yield + borrow together, and American single names keep the lumped-carry de-Am with a possible small residual ex-date kink. Indices (European, cash-settled) never touch the tree; ETFs and single names get the escrow tree only with a Bloomberg or hand-typed cash schedule and a non-zero rate.

### Comments for the presentation

- Lead with the epistemic rule: the forward is *measured* from the price level (every pair informs it), the discount is *ill-identified* (a slope teased out of small differences), and dividends are *not identifiable* from one expiry's chain at all — hence exogenous.
- Say "dividends are an input, borrow is a read, the forward is the fit" — that sentence survives any follow-up.
- If asked "why not fit dividends across the term structure": the two-parameter line per expiry has no room; a cross-expiry fit would trade per-expiry independence (maturity specials) for an assumption — the graph layer is where cross-node coupling lives, and it does not touch carry.
- The discount is held through the American de-bias; only the ATM-gap gate (5 vol bp, long-dated American) re-implies the rate — present it as the exception, not the rule.
- The mode choice matters for *dynamics*, not levels: cash escrow gives forward spot-elasticity $S/(S-\mathrm{PV})>1$, proportional and yield give exactly 1 (Note 06 eq. `elasticity`) — sticky-strike transport inherits it.
- Caveats to own: (a) default `rate = 0` means the escrow tree is off until a rate is set; (b) dividend import is Bloomberg-only — no Yahoo/Massive dividend feed; (c) `jointCarry` is API-only (the lens checkbox adds diagnostic columns, it does not set the field); (d) borrow reads need a term-matched rate curve to be trusted on HTB names (recorded verdict, open rider); (e) proportional modes are excluded from the joint solve and the escrow tree.
- Live-demo tell: on SPY with $r=0$ the Borrow column reads roughly $-(r+\text{div})$ — a few hundred bp negative — which is the flat-rate bias, not a market signal; set `rate` first if you want the column to mean borrow.

## 5. De-americanization and forwards

### 5.1 De-Americanization

**Crisp answer.** A plain Cox-Ross-Rubinstein tree with a **fixed 192 steps** on the production (batch) path and 501 on the scalar/reference path; depth does not adapt per maturity or moneyness (`dt = t/N`). No BBS, no Richardson extrapolation, no payoff smoothing: accuracy comes from a control-variate identity — the volatility `σ*` at which the *American* tree reprices the American mid is itself the European-equivalent Black vol, so the tree's level error largely cancels between its American and European legs. The inversion is a bracketed bisection (24 halvings) inside a Numba kernel that runs one scalar CRR per quote, quotes in parallel; the scalar path uses Brent. Only the **OTM side** is de-Am'd (puts below `F`, calls at/above), one root per strike on the **mid**; the same EEP is subtracted from bid, mid and ask.

**Tree** (`backend/volfit/core/american.py:125-146`, Numba twin `american_numba.py:50-87`): $u=e^{\sigma\sqrt{\Delta t}},\ d=1/u,\ p=\frac{e^{(r-q)\Delta t}-d}{u-d}$, backward induction with $V_n=\max(\text{continuation},\ \text{intrinsic})$ at every node. The kernel precomputes the powers $u^{j}$ once per price evaluation so the $O(N^2)$ induction is multiply/add/max only, and loops quotes under `prange` (`american_numba.py:103`).

**Discrete dividends — escrow** (`american.py:61-89`, `_escrow`): the recombining lattice diffuses on $S-\mathrm{PV}_0$ and the *actual* spot at step $n$ is base $+$ PV of the dividends still ahead at $t_n$ (Hull's escrowed-spot method), so early exercise is tested against the true cum-dividend spot. The cash amounts are rescaled by
$$\alpha=\frac{S-F e^{-rt}}{\sum_i D_i e^{-r\tau_i}}$$
so the escrowed forward reproduces the resolved forward exactly (`data/dividends.py:141-185`, `state.cash_dividend_schedule` `api/state.py:1480`); the tree then uses the **physical** `MarketSettings.rate`, `q=0`. This is opt-in by data: only when `dividendMode ∈ {discrete_absolute, mixed}`, a cash ex-date lies in $(0,t]$, and $0<\alpha\le$ max. Otherwise (the default `dividendMode="continuous"`) the tree runs on the lumped carry implied by the resolved pair: $r=-\ln D/t,\ q=r-\ln(F/S)/t$ (`api/quotes.py:217-218`).

**Inversion** (`american.py:319-379`): static screen $\text{intrinsic}<A<\{S \text{ (call)},K \text{ (put)}\}$ (:355-357); lower bracket at the CRR drift floor $\sigma_{lo}=\max(10^{-4},\,1.5|r-q|\sqrt{t/N})$ (:367); upper bracket doubled from $\max(0.5,2\sigma_{lo})$ up to `SIGMA_HI=4.0`; then `BATCH_BISECTIONS=24` halvings (:58) → $\sigma$ uncertainty $4/2^{24}\approx2.4\times10^{-7}$ (≈0.002 vol bp). Dispatch to Numba at :369-377, lockstep-NumPy fallback `_deam_bisect_numpy` (:266-316) agrees to tree rounding. The scalar `deamericanize` (:150-193) uses `brentq` (xtol 1e-8) on the 501-step tree and *raises* on a CRR probability outside (0,1); the batch returns NaN lanes instead.

**Quote prep** (`api/quotes.py:274-425`): keep the OTM side (:312) → tick floor: an OTM quote whose **bid** ≤ 3 ticks is dropped on real-feed chains (`TICK_FLOOR_TICKS` :104, :319) → pre-de-Am screen (non-positive bid; $|k|>1.5\cdot Z_{max}\sqrt{w_{atm}}$; output-preserving) → `_early_exercise_premiums` (:193-231):
$$A_{CRR}(\sigma^*)=A^{mid},\qquad \widehat{EEP}=\max\!\big(A^{mid}-P_{Black}(\sigma^*),0\big),$$
subtracted from bid, mid, ask (:362) so the dollar spread is preserved; a quote the tree cannot invert keeps $\widehat{EEP}=0$ and falls through to the European static-bounds filter → Black inversion to total variance → wing cut at `Z_MAX=4` ATM sd → **convex wing repair** (`calib/convex_deam.py`): per-strike $\max(EEP,0)$ leaves the de-Am'd call curve locally non-convex in the wings; the ATM core $|z|\le1$ is held byte-identical and each wing is Dykstra-projected onto {convex} ∩ {bid/ask band}, only when the worst normalized butterfly is below `CONVEX_TOL=1e-3` (liquid names untouched).

**EEP diagnostics**: `PreparedQuotes.eep` (per kept quote), `n_deamericanized`, `n_deam_input`, `screened` (named drop reasons), `vega_floored`; the status bar narrates "de-americanizing quotes" (`api/service.py:1066`).

**European underliers**: `ChainSnapshot.exercise_style ∈ {european, american}` (`data/types.py:113`; persisted, store schema v2). Set per source: Yahoo — `^`-prefixed cash indices are European, everything else American (`data/yahoo.py:93-99`; the universe's bare "SPX" maps to "^SPX"); Cboe / Nasdaq / HKEX — index security type → European (`cboe.py:116`, `nasdaq.py:170`, `hkex.py:256`); Bloomberg — per-contract `OPT_EXER_TYP` majority vote, " Index" fallback (`bloomberg.py:585, 632-634, 709`); Massive — per-contract `exercise_style` majority (`massive.py:1064-1068`); Eurex/SGX European; flat files American; snapshot files default European (`file.py:72`). A European chain skips de-Am (`quotes.py:348`) and the forward de-bias (`forwards.py:507`) entirely — locked byte-identical by `test_european_chain_passes_through_unchanged` and `test_european_chain_unaffected_by_reference_date`.

**Pitfalls identified (all fixed, all locked)**
- *ATM kink from EEP-contaminated parity slope*: raw American $C-P$ regression tilts $D$ (ITM-put EEP grows with $K$) → on long-dated SPY $D=1.0039$, $r=-0.41\%$ → the tree prices zero EEP on both sides → +28 vol bp jump at the put/call switch. - *48-step trees carry a systematic ~40 bp call-put odd/even lattice asymmetry*: the de-bias gate therefore reads its gap at full 192-step depth.

### 5.2 Forward fitting

**Crisp answer.** Yes — per expiry, equal-weight OLS of $y=C_{mid}-P_{mid}$ on $K$ over **every strike that carries a two-sided, uncrossed market on both legs** (no moneyness window on the regression itself), iterated with a MAD-based outlier trim; unknowns $F$ and $D$ per expiry. Robustness layers sit on top: a discount clamp to a physical rate band with an ATM/spread-weighted level re-derivation when it bites, a hard pin for zero-carry synthesized chains, and — American chains only — a de-Am fixed point on the near-ATM band that de-biases the forward and, when the sides still fail to join, the discount.

**Regression** (`data/forwards.py:208-212, 425-525`):
$$C(K)-P(K)=D\,(F-K)\;\Rightarrow\; y=a+bK,\quad D=-b,\quad F=a/D .$$
Pairs qualify iff `OptionQuote.mid` is not None on both legs (`types.py:54-60`: missing bid or ask, or bid > ask → excluded; no spread cap, no zero-bid rule at this stage — those live in quote prep). `MIN_PAIRED_STRIKES=3` (:105). Trim (:467-479): drop pairs with $|res_i|>4\cdot\max(1.4826\,\mathrm{MAD},\,10^{-4}S)$, at most 3 rounds, never below 3 survivors; dropped pairs reported as `n_outliers`, RMS as `residual_rms`. The regression is not bid-ask weighted; spreads enter only the clamp's level re-derivation.

**Discount clamp** (:492-501, reference-date path only): $D\in[e^{-0.30\,t},e^{+0.05\,t}]$ i.e. $r\in[-5\%,30\%]$ (`RATE_MIN/RATE_MAX` :122). When it bites, $F$ is re-derived from the well-identified *level*, not the slope:
$$F=\frac{\sum_i w_i\,(K_i+(C_i-P_i)/D)}{\sum_i w_i},\qquad w_i=\frac{e^{-(\ln(K_i/S)/0.10)^2}}{s^c_i+s^p_i+5\cdot10^{-4}S},$$
falling back to $F=S$ if $|\ln F/S|>0.5$ (:371-400). Horizon is day-granular ACT/365; a same-day expiry measures the clamp over the exact settlement instant (schema v7) else stands down (:403-422). Clean chains are byte-identical (the benchmark's $D=1.00335$ ≡ −4.5% must pass, hence −5%).

**Zero-carry pin** (:454-458): Massive's IV-synthesized chains (NBBO gated) are Black-repriced at $F=S,D=1$, zero spread — no parity content, and the provider's call/put IV asymmetry read as $-3.8\%$ short rates and a +1.7% 1y forward *inside* the band. `ChainSnapshot.zero_carry` (set at `massive.py:769`, persisted, store schema v5) pins $F=S$, $D=1$, rms 0; deliberately not inferred from zero spreads (EOD marks are bid==ask yet carry parity).

**Too few pairs**: `implied_forward` returns None → the expiry has no parity forward → it is outside the fit universe (`state.forwards` gates the ladder; `resolved_forward` raises "no parity forward (too few two-sided pairs)", `state.py:1557-1566`). The user can switch the per-expiry `ForwardPolicy.mode` to `theoretical` ($F$ = spot grown by `rate` and the dividend model, $D=e^{-rt}$) or `manual` ($F$ given, $D$ from parity else $e^{-rt}$) — `PUT /forwards/{ticker}/{expiry}`.

**American de-bias** (`_refine_american` :215-368; runs after the clamp, :507-514). Band $|\ln(K/F)|\le0.15$, capped at the 11 strikes nearest $F$ (fallback: nearest 11). Per candidate rate $r$: $q=r-\ln(F/S)/t$; de-Am **both** call and put mids (ITM included) on a coarse 48-step / 16-bisection tree; reprice European via normalized Black; re-imply $F$ at the **fixed slope** $-D$:
$$F\leftarrow\frac{1}{D}\,\overline{(y+DK)},\qquad y=\text{European }C-P,$$
iterate ≤ 6 rounds to $5\times10^{-5}$ relative. Gate: the switch gap read at full 192/24 depth with a tight ATM kernel,
$$g=\frac{\sum_i w_i(\sigma^c_i-\sigma^p_i)}{\sum_i w_i},\quad w_i=e^{-(\ln(K_i/F)/0.01)^2};$$
$|g|\le5$ vol bp → keep the raw discount bit-for-bit (all short-dated / clean chains). Otherwise bisect $r$ inside $[-5\%,30\%]$ to zero $g$ (monotone decreasing in $r$; ≤ 24 iterations, stop at 1 bp of gap or 1 bp of rate), $D=e^{-rt}$. Test contract (`test_forward_debias.py`): a flat-20% American chain gives raw $D=1.0047$ (a negative rate on a 5% chain) and a > 40 bp ATM jump; refined $r$ within 50 bp, $F$ within 20 bp, jump < 15 bp. Live SPY Jun-27: kink +28 bp → +1.1 bp, $r$ 6.24%. Identification limit ≈ ±1-2% in $r$ (a ridge of $(r,F)$ pairs kills the kink equally); engaged expiries' IV level shifts up ~0.7-0.9 vol pt (the old $D>1$ biased every IV low through $1/(DF)$).

**Joint borrow fixed point** (`data/carry_solve.py:164-262`):
$$b_{i+1}=b_i+\frac{1}{t}\ln\frac{F_{theo}(b_i)}{F_{parity}(b_i)},\qquad F_{theo}=(S-\mathrm{PV}_{div})\,e^{(r-q_{div}-b)t},$$
each pass de-Ams all paired mids at the *split* carry (rate, $q_{div}+b$, escrowed cash schedule), reprices them European on the same 96-step / 20-bisection tree, regresses parity; `TOL=1e-5`, ≤ 8 iterations, $|b|\le200\%$, ≥ 6 pairs; European chains short-circuit in one exact step. Planted 300 bp recovered at 299.8 bp vs 325.6 naive. It feeds fits only with `jointCarry=True` **and** converged $|b|\ge$ `jointCarryEngageBp` (`state.resolved_forward` :1571-1579, source `"joint"`); below the gate the parity forward is returned exactly. Carry view `GET /carry/{ticker}?joint=true` (`api/carry.py`): $\text{borrow}=\frac{1}{t}\ln\frac{F_{theo}}{F_{parity}}$, *identified* iff ≥ 6 pairs, rms ≤ $10^{-3}S$, not zero-carry — otherwise reported `unidentified`, never a silent zero; noise floor $\sigma_b=\mathrm{rms}/(t\sqrt n)$; $\partial\sigma/\partial b=\sqrt t\,N(d_1)/\varphi(d_1)\approx125\sqrt t$ bp per 100 bp.

**Calibration spot vs live spot**: fits are anchored at `anchor_spot` (`state.py:1297`, the spot at calibration). A spot move never re-runs the regression; the forward is transported, $F^1=F^0(1+\delta)$ for continuous/proportional dividends or $F^1=F^0+\Delta S\,e^{rt}$ for cash legs, $h=\ln F^1/F^0$ (`service.spot_forward_shift` :1097-1132). The parity cache is invalidated only on a chain refetch or market-settings change.

### Comments for the presentation

- Say "192-step CRR, fixed, no smoothing, no Richardson — and that is deliberate": the de-Am vol is a control variate, the tree error cancels between the American and European legs; what is left is ~1-2 vol bp in the body, a few bp in the low-vega put wing. Cutting to 128 steps was measured at ~15 bp drift on real SPY — the depth is a numerical target, not a speed dial.
- The speed story is the Numba kernel: 0.1 ms per quote, a 300-quote chain in ~30 ms, ~60-90× over vectorized NumPy; a five-expiry SPY chain that took 10 s now prepares in tens of ms, and the prepared-quote cache is a content digest so fit-only tuning never re-runs de-Am.
- Only OTM mids are inverted; ITM is never fitted. If asked "how big is the EEP", quote the fitted population (median |4| bp, up to ~60 bp in a six-month put wing), not the ITM wedge (hundreds of bp) — the note is explicit about which number is honest.
- The forward is a two-parameter line per expiry; the slope (discount) is the ill-identified parameter. The design ladder: regress where parity is informative → trim incoherent pairs → clamp an absurd slope and re-derive F from the ATM level → pin zero-carry synthesized chains → for American chains, de-bias F (and D only when the de-Am'd put/call sides refuse to join at the money).
- Be ready for "isn't the joint (r,F) under-identified?" — yes, ±1-2% in r along a ridge; the goal is the kink, not the rate, and the gate keeps every clean/short chain bit-identical. Borrow is a separate, opt-in fixed point (`jointCarry`, off by default) with an explicit `unidentified` state and a noise floor per expiry.
- Caveats to volunteer: the forward regression ignores bid-ask width (mid only) unless the clamp bites; day-granular t on the de-bias gate by design (0DTE EEP is negligible); discrete-dividend de-Am is opt-in via `dividendMode` and needs a physical rate (α > 0); the borrow read with a flat desk rate is biased 1:1 by the rate — a term-matched curve is a recorded rider.
- Demo tip: the Forwards lens shows parity vs theoretical vs active per expiry, `nOutliers`, residual rms, the zero-carry badge and the Joint/±σ columns; the smile chart's put/call join at the money is the visible proof of the de-bias.

## 6. Spot-vol dynamics

**« SSR / spot-vol : comment la dynamique choisie impacte-t-elle la paramétrisation, uniquement via un shift de strikes ? »**

**Crisp answer.** No — but almost, and deliberately so. The regime never touches the *fitted parameters*: LQD handles/θ, SVI-JW raw or JW parameters, the tail exponents α± and the affine LV nodal vols are all left byte-intact in the stored "current fit". What the regime does is wrap the fit's total-variance function $w_0(k)$ in a read-time view (`TransportedSlice`, served as `DisplayFit(model="transport")`) and re-label the quotes. For the three SSR-linear regimes the production view *is* a pure horizontal re-labelling — but of the **curve by $R\,h$**, not of the strikes by $h$: $\tilde w_1(k)=w_0(k+R\,h)$ with $h=\ln(F_1/F_0)$. Because the curve slides along its own skew, the ATM level moves by $R\,s_0\,h$, the skew *as read in moneyness* moves by $\kappa\,R\,h$ (a curvature term), and the wings/Lee slopes are unchanged. Only sticky-strike ($R=1$) is literally "vol fixed at a fixed strike". The two local-vol regimes are not shifts at all: `sticky_local_vol` uses the non-linear Hagan map $\ell_T(k,h)$ (strike-dependent displacement $(1+e^{-k})h$), and `sticky_local_vol_grid` freezes the Dupire grid in absolute strike and **reprices** through the PDE — there the SSR is an output, not an input.

### Regime × invariant × what moves

| Regime (`dynamicsRegime`) | UI label (Options / Scenario) | $R$ | Held invariant | Fixed-strike IV $\sigma(K)$ | Moneyness IV $\sigma(k)$ | Fitted params | LV affine grid nodes $x=\ln K/F$ |
|---|---|---|---|---|---|---|---|
| `sticky_moneyness` | "Mny" · "Sticky moneyness / delta" | 0 | $w(k)$ in moneyness | every strike's vol changes: $\sigma_1(K)=\sigma_0(k-h)$ | unchanged (identity) | untouched | $x$ unchanged ($\beta=1$: absolute $K$ rides the forward, $K\,e^{h}$) |
| `sticky_strike` (**default**) | "Strike" · "Sticky strike (smile fixed in absolute strike)" | 1 | $\sigma(K)$ at each strike | nothing | curve shifts left by $h$: ATM $+s_0h$, skew $+\kappa h$ | untouched | $x-\tfrac12 h$ (the "half-grid" proxy, $\beta=\tfrac12$) |
| `sticky_local_vol` | "LV" · "Sticky local-vol (SSR = 2 short-end rule)" | 2 (ATM limit) | local-vol *function* in absolute strike (Hagan approx.) | $\sigma_1(K)\simeq\sigma_0(K+\Delta F)$ | $w_1(k)=w_0(\ell_T(k,h))$: ATM $\approx+2s_0h$, wings displaced by $(1+e^{-k})h$ | untouched | $x-h$ ($\beta=0$: grid frozen in $K$) |

### Mechanics, item by item

**(1) Regimes implemented.** `Regime` enum in `backend/volfit/dynamics/ssr.py:37-49` (`sticky_moneyness`, `sticky_strike`, `sticky_local_vol`, `sticky_local_vol_grid`); map `_REGIME_SSR = {0, 1, 2, 2}` (`:52-57`); `ssr_of_regime` accepts a float as a custom $R$ (`:60-64`). Frontend: `frontend/src/components/options/SmallSections.tsx:266-272` (segmented labels Mny / Strike / LV / LV grid / SSR, with the titles quoted in the table), `components/ScenarioPanel.tsx:29-36`, `components/SpotPanel.tsx:228` (the "Regime · R" row), default `state/useOptions.ts:339`, help docs `lib/help/settingsDocs/events_graph_dynamics.ts:211-243`. **(2) What moves.** Production read path `transported_w` (`dynamics/transport.py:86-119`): if `is_exact_lv(regime)` → `w0(ell_T(k, h))` with `ell_T = log(exp(h + k) + expm1(h))` (`:74-83`), else `w0(k + R·h)` (`:113`). Sign convention (note Assumption "signs"): $h>0$ when the forward rises; a fixed strike's new label is $k-h$ (quotes, `service.py:1193`), the curve reads forward at $k+Rh$. ATM response: $\Delta\sigma_{ATM}=R\,s_0\,h+O(h^2)$ with $s_0=\partial_k\sigma|_0$ the fit's *numeric* ATM skew (`displayed_skew`). With equity skew $s_0<0$, spot up ⇒ ATM down for any $R>0$. The **scenario overlay** (`POST /scenario/ssr`, `service.py:2101-2140`) uses the older vol-space one-liner `shifted_smile` (`ssr.py:67-77`): $\sigma_1(k)=\sigma_0(k+h)+(R-1)\,s_0\,h$ — same ATM response to first order, but shape re-indexed by $h$ plus a uniform level, so it differs from the production $w$-space transport at second order away from ATM. Fitted parameters: `transport_record` (`service.py:1164-1203`) returns `FitRecord(prepared=replace(..., forward=f1, k=k-h), result=record.result, display=DisplayFit(model="transport", base_model=<lqd|svi|sigmoid>, slice=TransportedSlice(...)))` — `result` (θ, α±) is explicitly "kept intact so the graph universe still reads exact LQD coordinates". Nothing is re-implied into SVI-JW/LQD handles; ATM/skew/curvature, var-swap and Lee slopes are recomputed *numerically* off the wrapped curve (`_transported_display`, `:1143-1161`). The engine's optional finite-move ATM re-anchor (`atm_anchor`, `transport.py:114-119`) is never passed by any caller — it is off everywhere.

**(4) The forward.** `spot_forward_shift` (`service.py:1094-1130`): $F_1=F_0(1+\text{shift})$ under continuous yield / proportional dividends; under `dividendMode ∈ {discrete_absolute, mixed}` with a cash ex-date inside $T$, $F_1=F_0+\Delta S\,e^{rT}$ with $r=-\ln D/T$ — so $h_T$ differs per expiry. The discount $D$ and the borrow are held; $h$ is always computed from forwards, never from the raw spot ratio (the note's rule).

**(5) How a spot move reaches the app.** `AppState.spot_shift(ticker)` is per ticker, a proportional return vs `anchor_spot` = the *calibration* spot (`state.py:1297-1302`). Sources: `PUT /spot/{t}` = the dial → `follow="scenario"` (`spot.py:91-98`); `PUT /spot/{t}/follow market` → `sync_market_shift` to the prevailing spot (streaming book, else the newer of the last probe and the chain, `state.py:1199-1224`); the scheduler's `autoUpdate` (`off` default | `spot` = probe + transport every `autoUpdateSeconds`, 5 s | `snapshot` = quotes + spot, 15 s floor; `schemas.py:807-808`, `scheduler.py:139`); a streaming book syncs market followers at the spot-poll cadence and the SSE tick stream frames at the book (market) or at the dial (scenario) (`smile_layers.stream_frame`, `:80-93`). **(6) The "missing derivative" note** (`Docs/notes/12_spotvol_missing_derivative.tex`). A snapshot identifies today's marginals, not $\partial\sigma/\partial S$: through every arbitrage-free surface passes a family of admissible tomorrows, so the regime is a *choice* (Remark "ident") — worth **19.7 delta points** on an OTM put of the live long-dated SPY smile ($s_0=-0.354$) between $R=0$ and $R=2$ (Exercise 1: the delta correction is $\text{vega}\cdot(R-1)s_0$). Its §Limitations: the transport is first-order and shape-frozen (no vanna/volga/convexity response); $R$ is constant across strike and maturity on the analytic path; the regime is assumed, not estimated; large moves degrade quadratically (the re-anchor is only ATM-exact); the Hagan map and the linear $R=2$ transport separate by up to **111 vol bp** in the wings on a 5 % move; the frozen-LV answer is only as good as frozen local vol (empirically not invariant); the LV composite view has an integration test but no unit test of the composition.

**(7) Honest gaps.** No per-ticker or term-structure SSR; no estimator of the market's realized SSR (only the sticky-grid reprice *reports* one: 2.09 at 7 weeks → 2.00 at 18 months); two coexisting transports (production $w$-space vs the scenario's vol-space) agree only to first order; the ATM re-anchor is dead from the UI; the LV `xNodes` relabel uses one representative $h$; the sticky-strike grid rule is a proxy, not exact; no sticky-delta with a delta convention; a transported smile is not re-checked for butterfly/calendar arbitrage after a large move (the note advises regenerating for exotics).

**Réponse courte (FR).** Non, pas seulement un shift de strikes. Le régime ne modifie jamais les paramètres calibrés (LQD θ, α±, SVI-JW, grille LV) : il enveloppe la variance totale du fit dans une vue à la lecture, $\tilde w_1(k)=w_0(k+R\,h)$, $h=\ln(F_1/F_0)$, avec $R=0$ (moneyness), $1$ (strike, défaut), $2$ (LV), ou $R$ libre. C'est une translation de la *courbe* de $R\,h$ — seul $R=1$ est une pure re-étiquette des strikes ; l'ATM bouge de $R\,s_0\,h$, le skew lu en moneyness de $\kappa\,R\,h$, les ailes sont inchangées. Les régimes LV ne sont pas des shifts : carte de Hagan $\ell_T(k,h)$ (déplacement dépendant du strike) ou reprice Dupire à grille figée en strike absolu, où le SSR devient une sortie. Le forward suit $F_1=F_0(1+r)$ (additif sous dividendes cash), escompte conservé ; le prior, le graphe, la surface LV et le filtre sont transportés par la même règle ; « Recalibrer » est le seul chemin qui refitte.

## 7. Persistence & Kalman

### Persistence — what is persisted where the observation is precise, and how

**Crisp answer.** Nothing is persisted where the observation is precise — by construction, not by tuning. Every persistence mode adds least-squares rows of one shape, `r_j = sqrt(λ_j)·(O_j(model) − O_j(prior))/scale_j`, where `O_j` is a *functional of the smile* (a vol basket such as ATM / risk-reversal / butterfly, a vega-normalised call price at a delta strike, or the fair var-swap), never a model parameter; and the weight carries an **activation gate** `λ_j = B·gap_j/Σgap`, `gap_j = max(1 − π_obs,j/π_req, 0)^γ`, which is *exactly zero* — not small — once today's quotes identify the coordinate. Wings, deep tails and the var-swap level are held at yesterday's (spot-transported) shape; the ATM, and any collar/fly whose legs are quoted, are left to today's data. The precision of the prior is **not** taken from the previous fit's posterior covariance: `B` is a budget expressed as a percentage of the summed quote weights, and `π_obs` is the quote support at the legs — the design is a gap prior, not a covariance prior (that is the Kalman filter's job, below).

**Mechanics.**

1. *The universal row and the gate* (Note 13, eq. `universal`, `gap`; `calib/precision.py:66-86`, `calib/operators.py:278-349`). With `π_req = priorOperatorRequiredPrecision = 1` ("one effective quote suffices") and `γ = priorOperatorGapExponent = 1`:

   `gap_j = min(max(1 − π_obs,j / π_req, 0), 1)^γ`,  `λ_j = B · gap_j / Σ_i gap_i`,  `B = (priorOperatorStrengthPct/100) · Σ_q ω_q`.

   Proposition (no-damp, Note 13 `prop:nodamp`): `λ_j = 0 ⇒ r_j ≡ 0` for every θ, so the objective, its gradient and its Gauss-Newton model are independent of the prior value — a closed gate is a closed gate.

2. *How "precise" is measured — quote support, harmonically* (eq. `support`, `harmonic`; `operators.py:246-274`). Each leg `k_a` gets the kernel effective quote count `s_a = Σ_q ω̃_q exp(−(k_q − k_a)²/2b²)`, `b = priorOperatorBandwidth = 0.06`, weights normalised to mean 1. A basket `O = Σ_a c_a σ(k_a)` has `π_obs(O) = (Σ_a c_a²/(s_a+ε))^{-1}` — one dead leg unidentifies the whole risk-reversal, so its gate opens even when the other leg is liquid. Coupled statements persist coupled (Note 13 invariant 4; `prop:nullspace`): RR/BF coefficients sum to zero, so the basket row is invariant under a common level shift — it can never damp a market-wide vol move, which per-strike anchoring would.

3. *The strike anchors — a coverage deficit, not a precision ratio* (eq. `deficit`; `calib/prior.py:147-212`). Anchors sit at the Black-delta strikes `k = ½σ²τ − σ√τ Φ⁻¹(c)` for `priorAnchorDeltas = {2,5,10,25,40}Δ` per side plus ATM; weight `∝ (ρ_des(x_j) − ρ_obs(x_j))⁺ Δx_j` (KDE of today's quotes vs a desired coverage of the same mass over the wider span), normalised to the budget. The residual is the vega-normalised call-price difference against the prior's price, `1/vega` capped at 25× its minimum (`prior.py:58`). The *unmet fraction* `u` scales the companion var-swap row: a fully covered smile persists nothing.

4. *Space and time relabelling* (`api/prior_transport.py:50-58`, `prior.py:185-191`, `operators.py:32-36`). The prior is the saved node's LQD backbone (θ = (L, R, a) plus its stored `α±`, rebuilt in the same tail class), transported to today's forward under the live dynamics regime: `h = log(F_now/F_prior)`, `w̃(k) = transport(w_prior, h, regime)` (SSR / sticky-strike / sticky-LV, Note 12). Operators compare *vols* (`σ_prior(k) = sqrt(w̃(k)/τ_prior)` — the variance-time rescale cancels, so the *shape* persists, not the variance); strike anchors compare *prices* at today's `τ`: `w_target = w̃(k)·τ/τ_prior`. Leg strikes are located once on the transported prior and frozen.

### Kalman — how noise is estimated and filtered

**Crisp answer.** The observation filter is a per-node (ticker, expiry, fit mode) Kalman filter on three ATM handles of the LQD backbone, `x = (σ_atm, ∂σ/∂k, ∂²σ/∂k²)` at k = 0. The measurement `z` is the *data-only fit's* handles with `H = I`; its covariance `R` is **computed, not tuned**: the fit's own solution Jacobian propagated through the handle map in *stated* noise units (bid-ask half-spreads), inflated by realised misfit `ρ = χ²/(m−3)`. The process noise `Q` is a `√Δt` clock per handle (ATM 30 bp/√day) plus a spot-transport term and an innovation-gated widening for shocks. The gain is therefore a ratio of two computed covariances; the desk owns no "trust" dial. Default mode is `off`; `overlay` (compute and draw, calibration untouched) is the ratified pilot; `active` (one-stage MAP) exists, is validated on daily cadence, and is *not* usable at intraday cadence on short rungs.

**Mechanics** (Note 15 eqs. `state`, `measurement`, `kalman`, `cov-delta`, `resid-inflation`, `transport-handles`, `Q`, `active-map`).

*Model.* `x_t = Φ_t x_{t−1} + η_t`, `η_t ~ N(0, Q_t)`; `z_t = x_t + ε_t`, `ε_t ~ N(0, R_t)` (`15_kalman_filtering.tex:224-226`).

*Measurement (`calib/observation_measurement.py`, `api/observation_filter.py:135-201`).* `z` = `atm_handles` of the committed LQD backbone. Jacobian route (default): the calibrator's retained `J` (sqrt-weights and 1/vega folded in) has its data rows divided by the stated per-quote noise `s_i = max(half-spread_i, 1 bp) · max(1, √(30/DTE))` (`:109-132`), so `I_θ = JᵀJ` is the information in vol units; `R_x = G I_θ⁺ Gᵀ`, `G = ∂handles/∂θ` by central FD, with a *regularised* eigen-inverse (eigenvalues below `1e-10·λ_max` clamped **up**, so an unidentified direction inflates `R` finitely, `:98-119`); then `R = ρ·R_x`, `ρ = clip(χ²_fit/(m−3), 1, 25)` (`:122-140`) — a dense but self-contradictory cluster reads as noise and the gain falls (`test_contradictory_cluster_inflates_curvature_not_level`). Band-mode semantics come free (inactive hinge rows differentiate to zero). Fallback `factors` route: `R = diag(1/π)`, `π = (1/rms²)·density(n_atm/8)·spread(1/(1+s/0.05))·freshness(2^{−age/3d})·(1,1,0.01)` (`graph/precision.py:80-100`). With the filter *off* the same machinery gives the smile chart's error bars (`api/fit_uncertainty.py`).

*Prediction (`calib/observation_filter.py:141-249`).* First-order SSR transport for a log-forward move `h`: `atm' = atm + SSR·skew·h`, `skew' = skew + curv·h`, `curv' = curv` (`A_t = I`); `P⁻ = P⁺ + Q`, with

`Q = diag(q_h² Δt) + (0.10·|h|·(0.03, 0.05, 0.5))² + Q_adaptive`, `q = (30 bp, 0.02, 0.05)/√day`.

`Δt` comes from *snapshot* timestamps on the `calendar` clock (default) or the `session` variance clock (60 % of a day's variance in the exchange session, closed days 0; `_filter_dt_days`, `api/observation_filter.py:221-242`). Adaptive Q (`adaptive_inflation`, `:183-205`): per handle, if `ζ = |ν|/√(P⁻+R) > filterAdaptiveSigma = 3`, `P⁻ ← P⁻·(ζ/3)²` capped at 25 — a genuine 5-point overnight jump (~50σ under a 30 bp clock) reads as ~3σ and the gain rises toward the data; clean days are byte-identical.

*Update (`kalman_update`, `:94-137`).* `S = P⁻ + R`, `K = P⁻S⁻¹`, `m⁺ = m⁻ + K(z − m⁻)`, `P⁺ = (I−K)P⁻(I−K)ᵀ + KRKᵀ` (Joseph form, PSD for any gain, so the pilot cap `filterMaxGain` is safe). Production runs **diagonally** (`DIAGONAL_UPDATE = True`, `api/observation_filter.py:76`): the full-covariance update let junk curvature innovations drag the ATM level 3–28 vol points on coarse-strike ETF chains (EEM/EFA), worse than both baselines. The 95 % band drawn in overlay is the functional pushforward of the full 3×3 `P⁺` through the slice map (`_overlay_curves`, `:680-747`).

*Seeding and resets (`api:366-406`, `409-531`; `should_reset`, `calib:253-278`).* Seed = the transported saved prior with `cov = diag(1/(GRAPH_PRECISION·scale))` — active prior: std (10 bp, 1e-3, 0.01); no saved prior: the fit's own handles at bootstrap tier, std ≈ (45 bp, 4.5e-3, 0.045). Reset on a source / as-of change (store wiped), fit-mode change, quote edit, or a gap > `filterResetHours` = 96 h. One update per genuinely new observation, idempotent per (data_version, session_version).

*Active mode = one-stage MAP (`build_filter_prior`, `calib:288-339`; `_map_bookkeeping`, `api:534-611`).* The prediction enters the fit as three **ungated** stencil rows at `h = 0.06` — `σ(0)`, `σ(h) − σ(−h) = 2h·skew`, `σ(h) − 2σ(0) + σ(−h) = h²·curv` — with weights `λ_j = s_q²/Var(O_j)` (quote rows are unit-weighted vol errors, so the MAP objective is multiplied through by the typical stated noise `s_q²`). No second Kalman step touches the same quotes (`prop:nodouble`, locked to 1e-10 in `test_map_equals_kalman_posterior`): `P⁺` is read off the *full* solver information, capped at `P⁻`. Since today's innovation does not exist before the fit, the level row is gated by a fit-free ATM probe of the prepared mids and the shape rows by the previous step's innovation (`api:271-305`).

| `filterDataOnlyPrepass` | off | extra data-only fit so `z` is persistence-free; off = flag `contaminated` |

**Overlap and interaction.** The two answer different questions with different sufficient statistics (Note 15 §2, `15_kalman_filtering.tex:209-232`): persistence carries a *gap* and refuses to invent signal where the market did not speak; the filter carries a *covariance*, infers what a noisy market probably meant, and is *always on* at that weight. Both can be on. `overlay` + `hybrid` has no feedback (the posterior never enters a fit); the only coupling is the `contaminated` flag when `z` came from a persistence-anchored fit (`filterDataOnlyPrepass` removes it exactly). `active` + any calibration-prior mode triggers the **hard-coded auto-exclusion** (`api/prior_mode.py:61-80`; `test_auto_exclusion_truth_table`): ATM/RR/BF operators, smile factors and the near-ATM strike anchor are dropped — anchoring the handles to the same previous state that already enters as `m⁻` would count it twice — and what survives is what the state does not carry: the deep-tail 2Δ/5Δ anchor (`test_affine_prior_lv_tail_anchor_survives_an_active_filter`), the WingL/WingR rows only under `wingOperatorsUnderActiveFilter` (merged beside the MAP rows), and the graph's dark-node baseline; the saved prior also *seeds* the first filtered state. The anchoring axis shows the split on one node (Free vs + Prior isolates the gap prior; + Filter adds the temporal block — a preview under `overlay`, production under `active`), and the Series lens runs the same three as **lanes** — `LQD-n free`, `+ prior` (= hybrid), `+ prior + filter` (= hybrid + active) — as temporal chains over stored frames (`api/series_presets.py:26-45`), each lane keeping its own Kalman ring for the Lanes-stage FilterTimeline (bands m⁻±σ / z±σ_R / m⁺, ζ strip, gain sparkline, stacked Q breakdown, reset and contamination markers; `frontend/src/components/FilterTimeline.tsx`, `series/LanesFilterPanel.tsx`).

**Memory horizon.** Persistence has no horizon: the prior is the last saved fit, at full strength, until overwritten or adopted (the graph baseline, not the calibration gate, ages it with a 30-day half-life). The filter's memory is set by the ratio `R/Q` and is *short by design*. For the scalar random walk the steady-state gain is `K = P⁻/(P⁻+R)` with `P⁻ = (Q + √(Q² + 4QR))/2`, `Q = q²Δt`; the previous posterior's weight decays as `(1−K)ⁿ`, half-life `ln2/(−ln(1−K))` steps. Under the defaults (`q = 30 bp/√day`, calendar clock) for the ATM handle:

| Cadence | σ_R (ATM, from the Jacobian route) | K | half-life |
|---|---|---|---|
| daily | 3 bp (tight SPY belly) | 0.99 | 0.15 step ≈ no memory — the state *is* today's fit |
| daily | 10 bp | 0.91 | 0.3 step |
| daily | 30 bp (wide / short-dated, ρ-inflated) | 0.62 | 0.7 day |
| 30 min | 3 bp | 0.74 | ~15 min |
| 30 min | 10 bp | 0.35 | ~50 min (1.6 steps) |
| 30 min | 30 bp | 0.13 | ~2.4 h (4.8 steps) |

At the design's `q = 10` the daily/10 bp case gives K = 0.62 (half-life 0.7 day) and the 30-min/10 bp case K = 0.13 (2.4 h). A weekend on the calendar clock adds `√3·30 ≈ 52 bp` of prediction std, so Monday's state is essentially Monday's data (the session clock stops that accrual — a weekend measured 55 bp, the same as one overnight); a gap > 96 h reseeds; a > 3σ surprise inflates `P⁻` and collapses the memory at once. The user tunes the horizon with `filterProcessVolBpSqrtDay` (lower = longer memory), the clock and the shape scales; the audit statistic is std(ζ) ≈ 1 on the FilterTimeline.

**Honest limitations** (`15_kalman_computed_trust.tex:991-1017`; series finding 2026-09-10/11). The diagonal update discards cross-handle information. The session clock is measured but not default; at the default shape scales ζ_skew ≈ 1.8 and ζ_curv ≈ 6.4 on the 30-min cadence, worst short-dated (per-maturity handle scales are the recorded follow-up). The active-path surprise gate is unit-locked, not sweep-validated — the open item before any active-by-default. The short end is the weakest bucket (the √(30/DTE) floor sizes R honestly, but honest uncertainty is not signal). The state is per node; the carrier is the LQD backbone. And the **active MAP block is unusable at intraday cadence on short rungs**: on the 0DTE store the per-node predictions were calendar-inconsistent (curvature +0.68 vs −0.44 on adjacent dailies), the symmetric repair ground 451 s and died in a NaN; with calendar coupling off a frame still took 313 s, failed 10 slices and fit at 299 bp median rms (the predicted variances collapse on a one-day rung); the user's NVDA 5-min series diverged frame by frame (rms 7.9 → 161 bp, ATM pull −1,097 bp) — hence `lane_warnings` on any active-filter lane of a sub-day series, the 300 s frame budget, and `overlay` for intraday work.

### 8.1 LQD model equation + ledger

**(a) On the slide**

LQD = **Log-Quantile-Density** (Note 01's subtitle: "a log-quantile-density parametrization"; its lecture edition reads the same object as a *rubber ruler* — a monotone transport from ranks to log-returns). For one expiry, with $X=\log(S_T/F_T)$, $Q=F_X^{-1}$ the quantile and $q=Q'$ the quantile density:

$$
\ell(u)=\log q(u)= -\log u-\log(1-u)+\underbrace{(1-u)L+uR+\sum_{n=2}^{N}a_nP_n(1-2u)}_{g(u)}
\qquad\text{(Note 01, eq. lqd\_main)}
$$

$$
f_X\!\big(Q(u)\big)=\frac{1}{q(u)}=u(1-u)\,e^{-g(u)}>0\ \text{ for every }\theta
\qquad\text{(no butterfly, by construction)}
$$

Generalized tails (book ch. 2, eq. skeleton): add $-\alpha_-\log\ell_-(u)-\alpha_+\log\ell_+(u)$, $\ell_-(u)=1-\log u$, $\ell_+(u)=1-\log(1-u)$, $\alpha_\pm\in[0,\tfrac12]$; $\alpha=0$ is the line above exactly.

Pricing chain, all on the log-odds line $z=\log\frac{u}{1-u}$ (book eqs. lqd, ledger, call):
$$
\theta\to g\to Q(z)=\mu+\!\int_0^z e^{g(\Lambda(t))}dt\ \to\ \mu:\ \mathbb E[e^X]=1\ \to\
C(k)=G(z_k)-e^{k}(1-u_k),\quad G(z)=\int_z^\infty e^{Q}\Lambda(1-\Lambda)\,dt\ \to\ \sigma_{\rm imp}(k)
$$

Tail scales and Lee slopes: $A_L=e^{g(0)},\ A_R=e^{g(1)}$ (eqs. AL, AR); finite forward $\iff A_R<1$ (eq. AR\_condition); $\beta_L=\psi(1/A_L),\ \beta_R=\psi(1/A_R-1)$, $\psi(p)=2-4(\sqrt{p^2+p}-p)$ (eqs. lee\_psi, lee\_slopes).

Exact ATM handles (eq. atm\_handles) from $C'(0)=-(1-u_0)$, $C''(0)=f_0-(1-u_0)$ (eq. Cder): $\sigma_0=\sqrt{w_0/\tau}$, $s_0=\partial_k\sigma_{\rm imp}(0)$, $\kappa_0=\partial_{kk}\sigma_{\rm imp}(0)$.

One-expiry core objective (eq. calib\_objective):
$$
\min_\theta\ \sum_i\omega_i\Big(\frac{C^{\rm LQD}(k_i;\theta)-\mathrm{Black}(k_i,w_i)}{\partial_\sigma\mathrm{Black}(k_i,w_i)+\eta}\Big)^2+\lambda\sum_{n\ge4}n^{2r}a_n^2
$$

**(b) Say**

Most smile models write down the implied-vol curve and then check, afterwards, that the density it implies is positive. LQD inverts the order: it writes down the probability law first and reads the smile off it by integration.

The object is the quantile density $q=Q'$ of the log-forward return — how fast successive probability ranks travel through return space. We model its logarithm, so $q$ is positive whatever the coefficients, $Q$ is increasing, and the return density $u(1-u)e^{-g}$ is non-negative before any quote has been fitted. Butterfly arbitrage is not penalised; it is unreachable.

Read the basis from the outside in. The two logarithmic terms are the skeleton: they make the quantile linear in log-odds at both ends, which is an exponential return tail, which is exactly the linear total-variance wing Lee's formula allows. Their scales are the endpoint values $A_L=e^{g(0)}$ and $A_R=e^{g(1)}$. The Legendre modes shape the body between the tails in a well-conditioned orthogonal basis. The two roles do not fight: the production chart's coordinates are $(\log A_L,\log A_R,a)$, so a body mode cannot drag the asymptotic wings while the solver moves, and the right scale is pushed through a logistic so the one hard wall — $A_R<1$, a finite forward — sits at infinity. Every finite iterate is an admissible law.

Pricing is one cumulative integral. On a log-odds grid of half-width 40 we accumulate $e^{g}$ by fourth-order cumulative Simpson to get $Q$, choose the single shift $\mu$ that makes $e^X$ mean one, and accumulate the upper share $G(z)=\mathbb E[e^X\mathbf 1\{Z>z\}]$. A call is $G(z_k)-e^k(1-u_k)$: the share of the forward above the strike minus the strike times the exercise probability. Off-grid, $Q$ and $G$ are interpolated by cubic Hermite polynomials on their exact nodal derivatives $dQ/dz=e^g$ and $dG/dz=-e^{Q}u(1-u)$; the strike root $Q(z_k)=k$ is a Hermite–Newton solve to machine precision; the truncation tails are added analytically. The Black inversion of those prices is the smile.

Three quantities come out in closed form and are what a trader asks for: ATM vol, skew and curvature, from the first two log-strike derivatives of the call at $k=0$. Those three handles are what the prior, the Kalman filter and the graph carry — not the raw $\theta$, which is not unique across fits. Above them sits the market's own vocabulary — risk reversals, butterflies, the var-swap level — each with a "move one package, hold the handles" direction in coefficient space.

The default order is 16, raised from 6 after low-vol names whose quoted strip spans four sigmas left a $\pm20$ bp equioscillating shoulder residual at $N=12$; the effective order is capped at two quotes per parameter, so a 19-quote 0DTE book still fits a clean $N=8$ in tens of milliseconds. The tail exponents $\alpha_\pm$ are the one thing the optimizer may not touch: a small $\alpha>0$ is indistinguishable from $\alpha=0$ on a finite strike strip while flipping the moment domain, so they are a per-underlier policy input — a scenario dial, not an estimate.

**(c) If asked**

- *"Seventeen parameters — you are overfitting."* Least squares in vega-normalised price with a high-order ridge $\lambda n^{2r}a_n^2$ ($\lambda=10^{-6}$, $r=1$) and a two-quotes-per-parameter cap. On 1,576 replayed NBBO nodes LQD-12 fitted 7.6 bp in-sample / 9.8 bp out-of-sample against SVI-JW's 24.3 / 26.8; OOS tracks in-sample, the signature of signal five parameters cannot express, not of overfit (deck Q&A, slide 6).
- *"Are the coefficients stable day to day?"* Raw $\theta$ is not unique (Note 01 §Limitations); stability is defined and carried at the handle level $(\sigma_0,s_0,\kappa_0)$, which is why the prior, filter and graph transport handles, never $\theta$.
- *"What can the model not represent?"* Atoms — a jump-to-default mass or a pinned settlement price — only as a sharp continuous feature; and positive is not plausible: an unregularised high-order fit can be spiky yet arbitrage-free; the ridge and the bid–ask band handle that.
- *"Why fix $\alpha$ instead of fitting it?"* The $\alpha\downarrow0$ limit is non-uniform: every $\alpha>0$ gives Lee slope zero (all moments finite), $\alpha=0$ gives a positive slope; on a finite strip the two are indistinguishable, so per-slice estimation is ill-conditioned by construction (book ch. 2 §2.5.4; roadmap ruling 2026-08-12).
- *"Which coordinates does the graph move?"* $h=(\sigma_0,s_0,\kappa_0)$, exact for every slice; the internal orthogonal chart works in $(w_0,s_0,\kappa_0)$ with $w_0=\sigma_0^2\tau$ and the graph adapter converts.

### 8.2 Lee boundaries and tail modelling

**(a) On the slide**

Lee's moment formula (Note 09 last-quote edition, thm. lee, eq. psi; Lee 2004):
$$
\beta_R=\limsup_{k\to+\infty}\frac{w(k,T)}{k}=\psi(p^*),\qquad
\beta_L=\limsup_{k\to-\infty}\frac{w(k,T)}{|k|}=\psi(q^*),\qquad
\psi(p)=2-4\big(\sqrt{p^2+p}-p\big)\in[0,2]
$$
$p^*=\sup\{p:\mathbb E[S_T^{1+p}]<\infty\}$, $q^*=\sup\{q:\mathbb E[S_T^{-q}]<\infty\}$; $\psi$ strictly decreasing, $\psi(0)=2$, inverse $p=\tfrac1{2\beta}+\tfrac\beta8-\tfrac12$. The ceiling 2 is a supremum, not a member (rem. boundary): at $\beta=2$ the Durrleman density reads $g(k)=\frac{\alpha-2}{4k}+O(k^{-2})$ (Note 02 moments, eq. gboundary) — negative in one wing.

LQD: $\beta_L=\psi(1/A_L)$, $\beta_R=\psi(1/A_R-1)$, $A_R<1$ (eq. lqd\_wings) — identities of the fit, no penalty. Generalized tails $\alpha_+>0$: $w(k)\sim\tfrac12\big(\tfrac{\lambda_+}{1-\alpha_+}\big)^{1/(1-\alpha_+)}k^{(1-2\alpha_+)/(1-\alpha_+)}$ (book eq. rightsublinearwing) — Lee slope 0, sublinear wing; at $\alpha=\tfrac12$, $w\to2\lambda^2$ (Gaussian rate). Calendar tail coupling with common $\alpha$: $\lambda_{\pm,j+1}\ge\lambda_{\pm,j}$ (eq. tailscalecalendar).

SVI-JW (Note 02, eqs. jw\_def, jw\_units): $p=\frac{b(1-\rho)}{\sqrt{w_0}},\ c=\frac{b(1+\rho)}{\sqrt{w_0}}$, $\beta_L=p\sqrt{v\tau},\ \beta_R=c\sqrt{v\tau}$; no-arb (prop. jwnoarb): $\tilde v\ge0$, $\max(p,c)\sqrt{vt}\le\beta_{\max}=1.95$. Penalty rows (eq. svi\_penalties): $W\max(-(a+b\sigma\sqrt{1-\rho^2}),0)$, $W\max(b(1+|\rho|)-\beta_{\max},0)$, $W=10^3$. Structural chart (eq. structural): $\beta_L=\beta_{\max}\,\mathrm{logistic}(\ell)$, $\beta_R=\beta_{\max}\,\mathrm{logistic}(r)$, $w^*=\mathrm{softplus}(h)$, $\kappa^*=e^q$ — every iterate strictly Lee-clean.

**(b) Say**

Lee's result is model-free and worth stating slowly. Take any arbitrage-free smile and follow total variance out into a wing. It cannot grow faster than linearly in $|k|$, and the slope is pinned to the last finite moment of the terminal price by the map $\psi$: the more moments exist, the flatter the wing; a slope of 2 corresponds to no moment at all beyond the first. The ceiling is a supremum, not a point you may sit on — at exactly 2 the implied density changes sign in the wing.

Each model meets this differently. LQD does not police it: the wing slopes are algebraic identities of the two tail scales, $\beta_R=\psi(1/A_R-1)$, so the only thing to enforce is the finite-forward wall $A_R<1$, and the logistic chart puts that at infinity. A heavier tail means a larger scale and a steeper wing, and equity fits use a sliver of the admissible range. When we switch on the generalized tails, $\alpha>0$ makes all moments on that side finite: the wing turns sublinear and Lee's slope is zero — which is why $\alpha$ is a dial, not a fitted parameter.

SVI-JW carries its wings in its parameters $p$ and $c$, so we cap $\max(p,c)\sqrt{vt}$ — at 1.95, not 2. The buffer was bought after a production SPY wing landed at exactly 2.0000: the penalty hinge is zero on the broken boundary itself, and a parameter set passing both screens with $g(10)=-0.0485$ was on the table. The structural chart now writes the wings as $\beta_{\max}\cdot\mathrm{logistic}$, so the cap is never touched, and a separate certificate scans the Durrleman density on 801 points across the traded range — the belly, where quotes exist. A slice that fails cannot become a mark; it gets one repair fit and, failing that, blocks export.

Then the part the audience will push on: past the last quote there is no data. Everything inside Lee's cone is admissible, and the quotes cannot select among admissible tails. So a wing is a stated contract per model — exponential with a reported scale for LQD, linear for SVI — not an estimate. We measure arbitrage in the extrapolated region on every fit (advisory), we can lean on it with tapered hinges worth a quarter of a quote each, and at publish time we project the exported wings onto the arbitrage-free cone without touching the traded core. A wing knob becomes a calibrated variable exactly when an instrument observes it: the local-vol put-wing slope is free only under a var-swap quote.

"Tail persistence" is the prior's side of this: the previous day's tail rides over as raw $\theta$ plus the $\alpha$ fields, defended by a deep-strike anchor at 2 and 5 delta and an absolute var-swap row, while the graph and the filter carry the body only — three handles — so the tail is never transported or filtered.

**(c) If asked**

### 8.3 Penalty function

**(a) On the slide**

What `least_squares` actually sees is one stacked residual (`models/lqd/calibrate.py:226`):
$$
r(\theta)=\big[\ \underbrace{\text{fit}}_{\text{data}}\ \big|\ \underbrace{\sqrt\lambda\,n^{r}a_n}_{n\ge4}\ \big|\ \text{cal}\ \big|\ \text{calk}\ \big|\ \text{barrier}\ \big|\ \text{vs}\ \big|\ \text{pa}\ \big|\ \text{pvs}\ \big|\ \text{op}\ \big],\qquad \min_\theta\ \|r(\theta)\|^2
$$

Data term (Note 07 measure, eq. master), in vega-normalised price units $m_i=\frac{C^{\rm model}-\mathrm{Black}}{\partial_\sigma\mathrm{Black}+\eta}$ (eq. vega):
$$
\sum_i\lambda_i\Big[(m_i-\mathrm{hi}_i)_+^2+(\mathrm{lo}_i-m_i)_+^2+\theta_{\rm mid}(m_i-\mathrm{mid}_i)^2\Big],
\quad\text{mid: lo=hi=mid;}\ \ \text{haircut (eq. haircut): } \mathrm{lo}=\min(\mathrm{bid}+h,\mathrm{mid}),\ \mathrm{hi}=\max(\mathrm{mid},\mathrm{ask}-h)
$$
Weights are **target distributions with a density correction** (eq. tvweights): $\omega_i=\max(\mathrm{raw}_i,\varepsilon)\,s_i/\bar s$, $s_i$ the Voronoi cell width in log-strike; raw $=1$ (`uniform_density`), $\mathrm{TV}_i$ (`tv_density`), $\phi(d_+)$ (`vega_density`), OTM $|\Delta|$ (`delta_density`); `equal` = one vote per quote, no correction. Mean-normalised to one, capped at 10×.

Regularisers and priors:
$$
\lambda\!\sum_{n\ge4}n^{2r}a_n^2
\ +\ W_{\rm cal}\!\sum_m\mathrm{taper}_m\big(C_{\rm near}(k_m)-C_{\rm far}(k_m)\big)_+^2\ \text{(N10 eq. price\_rows)}
\ +\ \log\!\big(1+e^{s(A_R-c)}\big)^2
\ +\ \omega_{\rm vs}\big(\sigma^{\rm model}_{\rm vs}-\sigma^{\rm quote}_{\rm vs}\big)^2\ \text{(N08 eq. vs\_resid)}
$$
$$
+\ \sum_j\lambda_j\Big(\frac{O_j(\theta)-O_j(\text{prior})}{\text{scale}_j}\Big)^2\ \text{(N13 eq. universal)},\quad
\lambda_j=B\,\frac{\mathrm{gap}_j}{\sum_i\mathrm{gap}_i},\ \ \mathrm{gap}=\Big(\mathrm{clip}\big(1-\tfrac{\pi^{\rm obs}}{\pi^{\rm req}},0,1\big)\Big)^{\gamma},\ \ B=\tfrac{\texttt{Pct}}{100}\sum_q\omega_q
$$
$$
+\ \tfrac12\big\|\mathcal H(\theta)-m_t^-\big\|^2_{(P_t^-)^{-1}}\ \text{(N15 eq. active-map, filter mode active only)}
$$
Event clock (N11 eq. clock): $\tau_{\rm days}(t)=365\,t+\sum_{t_e\le t}N_e$, every $w=\sigma^2\tau$ in the fit uses $\tau$.

**(b) Say**

Start with the data term, because everything else is measured against it. A residual is a price error divided by vega, so it reads as a vol error while every iterate stays a genuine density. In mid mode it is least squares to the mid. In band mode it is a hinge: zero anywhere inside the bid–ask, quadratic outside, plus a mid anchor at weight 0.05 that selects one point of the valley the hinge leaves open — the minimiser set with no anchor is the whole product of bands. Haircut mode shrinks each band by a fixed vol amount, half a vol point by default; a quote tighter than the haircut collapses to a mid fit on that strike. The weight schemes are not weights but targets: a scheme names the distribution of weight in log-strike we want, and the Voronoi correction divides out the listing grid so a dense cluster of strikes cannot vote more than once. `equal` is still the default — one vote per quote.

Then the regularisers, each with one job. The ridge $\lambda n^{2r}a_n^2$ damps high Legendre modes and leaves skew and curvature free. The barrier keeps $A_R$ from the wall. The var-swap row pins the tail-loaded integral to a quote when one exists, at ten percent of the summed quote weight. The calendar rows are in price space at fixed forward moneyness, confined to the common quote support and tapered at its ends, at weight $10^6$ — a hinge that is zero wherever the near call is below the far call.

The prior is not a shrinkage. Each operator — ATM, 25-delta risk reversal, butterfly, var-swap — gets a budget times a gate. The gate is one minus the observed precision over the required precision, clipped to $[0,1]$: where the live quotes already identify the operator, its weight is exactly zero; where they do not, the transported prior fills in. Hybrid mode adds a deep-strike anchor below the shallowest active wing operator. So a dense cluster of quotes drives the gate to zero and the prior switches itself off. Data wins.

The Kalman filter runs on the three handles. In overlay it predicts, updates and draws — it never feeds back into the fit, so it cannot double count. In active mode the prediction enters the fit once, as a Mahalanobis row on the handles with the predicted covariance, and the persistence operators that overlap those handles are dropped automatically. Measurement noise is not a knob: it is propagated from the fit's own Jacobian and inflated by the realised misfit.

The solver: each expiry is fitted independently by trust-region least squares with the analytic Jacobian; each adjacent interface is screened for an identified calendar violation; only the violation-connected components are jointly Gauss–Newton-repaired on a block-bidiagonal stack, escalating the interface weight tenfold up to three times; an active-set exchange then adds hard rank rows until the exact full-line certificate passes. A clean ladder returns its independent fits byte for byte. What the trader sees is an rms in vol bp that mirrors the objective — distance to mid, or band violation — pooled across expiries, with a 50 bp budget, a Lee gate at 2, the calendar certificate, the belly certificate and data age as readiness gates.

**(c) If asked**

- *"Why a hinge and not weighted least squares to mid?"* Inside the band the market has expressed no preference; the anchor's weight 0.05 means entering the band divides the data term's strength by twenty in its contest with the ridge, the prior and the calendar rows — that is the point (Note 07 measure, prop. valley).
- *"Does the prior smooth the market away?"* No: the gate is exactly zero where quotes identify an operator (prop. nodamp); the prior only holds what nothing observes. The covariance is diagonal by design; there is no Mahalanobis metric in the persistence term — that form lives in the active filter row.
- *"Kalman plus prior plus quotes — three votes for the same data?"* Overlay never feeds back. Active is a one-stage MAP: one residual block, persistence auto-excluded on overlapping handles, no second update.
- *"Is calendar a soft penalty then?"* Penalty and escalation first, then hard rank rows in the exchange, and the exact certificate is the publish authority; a violation that survives is reported as irreducible slack, never flattened.
- *"What if the calendar and the quotes disagree?"* The band-relaxation diagnostic bisects the smallest symmetric band widening under which the pair certifies and reports it in vol units — the accepted surface is untouched.

### 8.4 Graph transport and regularization

**(a) On the slide**

Node state — the **increment** of the three exact ATM handles from the transported prior, three independent fields (Note 14, heuristic l.100-108, l.111-118):
$$
z_i=x_i^{1}-x_i^{0}\in\mathbb R^3,\qquad x=(\sigma_0,s_0,\kappa_0),\qquad \text{lit: } d_s=\text{today's fit}-x^0_s;\quad \text{dark: no observation}
$$
Edge contract (Note 14 messages, def. edge, eq. beta): amplitude and precision never mix,
$$
z_i=\beta_{ij}\,z_j+\epsilon_{ij},\quad \epsilon_{ij}\sim\mathcal N(0,1/p_{ij}),\qquad
\beta_{i\leftarrow j}=(T_j/T_i)^{\alpha_T},\ \alpha_T=1\ \text{(constant total-variance injection)}
$$
Precision-message operator and posterior (eqs. qmsg, posterior, rd):
$$
Q_{\rm msg}=\sum_{j\to i}p_{ij}\,u_{ij}u_{ij}^{\!\top},\ u_{ij}=e_i-\beta_{ij}e_j;\qquad
z_i\mid z_{\cdot}\sim\mathcal N\Big(\frac{\sum_jp_{ij}\beta_{ij}z_j}{q_i},\frac1{q_i}\Big),\ q_i=\sum_jp_{ij}
$$
$$
Q^+=Q_{\rm msg}+D_\kappa+H^{\!\top}R_dH,\quad b^+=H^{\!\top}R_d\,d,\quad \hat z=(Q^+)^{-1}b^+,\ \Sigma^+=(Q^+)^{-1},\quad r^d_s=\big(1/r^{\rm cal}_s+1/p^0_s\big)^{-1}
$$
Separation of signal and precision (eq. hops): $\mathbb E[z_C]=\beta_2\beta_1\mathbb E[z_A]$, $\ \mathrm{Var}(z_C)=(\beta_2\beta_1)^2\mathrm{Var}(z_A)+\beta_2^2/p_1+1/p_2$ — distance costs confidence, never amplitude. Reported confidence $\pi_i^+=1/K^+_{ii}$ (the marginal), never $(Q^+)_{ii}$.

Smooth field, legacy (Note 14 extrapolation, eq. Qdelta): $Q_\Delta=D_\kappa+\eta L^{\beta}_{\rm dir}+\lambda(A_\rho+\nu I)^{-1}$ — local smallness $\kappa$, directed smoothness $\eta$, unbalanced-OT tangent norm $\lambda$ (shipped $\lambda=0$).
Layered, default (Note 14 three priors, eqs. directed, dynamics, dirichlet): $z_{i,t}=\beta_{ij}z_{j,t}+u_{i,t}+\epsilon_{ij,t}$, $u_{i,t+\Delta}=2^{-\Delta/H_i}u_{i,t}+\omega$; directed pass then harmonic completion $\hat z_F=-Q_{H,FF}^{-1}Q_{H,FS}\,d_S$.

**(b) Say**

The graph's nodes are smiles — one per underlying and expiry — and what lives on a node is not a smile but a move: the increment of the three exact handles, ATM vol, skew and curvature, from where the transported prior said the node would be. Regularising increments rather than levels makes "no change" the default answer; data has to earn every departure from the prior. Lit nodes are the richly quoted expiries whose fit gives an innovation; dark nodes are single-name expiries, far tenors, the weekly that traded twice today. A dark quote is never an observation — it may test the answer afterwards, never shape it.

An edge is a contract with two numbers that never mix. $\beta$ says what the receiver's move should be given the sender's: for a calendar edge with $\alpha_T=1$ it is the ratio of maturities, so one vol point at six months is two at three months and half a point at one year — constant total variance. $p$ says how much the relation is trusted. The posterior at a dark node is then exactly what Gaussian conditioning gives: incoming messages are precision-weighted and averaged, and independent precisions add. The consequence is the separation the framework is built for. Follow a signal across two edges: the mean is $\beta_2\beta_1$ times the source, undiminished; the variance picks up $1/p$ per hop. Distance costs confidence, never amplitude. The legacy smooth-field operator could not do this — a row-normalised Laplacian discards how much incoming information a node has, and its mean strength and its confidence are coupled — which is why it now sits under Advanced.

Regularisation is two scalars per node and one per edge. $\kappa$ is the cost of moving alone, a proper prior toward the baseline; $\eta$ multiplies the edge precisions and sets the reach; the cross-ticker multiplier scales index-to-name edges against the calendar chain. The benchmark pack ratified $\eta=10$ and cross-mult 25. The layered default adds direction and time on top: a directed pass through dependencies with a residual that decays on a half-life, then harmonic completion of the free nodes.

The evidence is leave-one-out over three regimes: each calibrated node is withheld, predicted from the rest, and scored against its own fit. On fully dark single names the graph improves the transported baseline by 8 to 14 bp in the August 2024 spike and 4 to 7 bp out-of-sample in October 2022, with standardised residuals of unit width; in the calm July 2023 regime it is within a basis point and never negative. On indexes the full LOO gains are 17 to 76 bp. Propagation earns its keep in stress and does not hurt in calm.

After a Run every node draws its inferred smile — the posterior handles retargeted on the node's own shape, violet, badged. It transports with spot like a fit, and it is never a fit: never committed, never a prior, never an input to a calibration.

**(c) If asked**

- *"Is this interpolation across names dressed up?"* No — the unknown is the increment from a transported prior, not a level; a node with no informative neighbour returns "no change" with a wide band, and the LOO scores that band: ζ std 1.02–1.10 on dark names in stress.
- *"Did you learn the betas from data?"* Yes, and the verdict was recorded and held: learned betas gain fractions of a bp on the dark-name split and regress the full LOO by 2 to 8.6 bp; the edge builder keeps the hand-set calendar priors, the learned file stays diagnostic (ruling 2026-07-19).
- *"Where is the optimal transport?"* Implemented as the third term of the smooth-field precision and shipped at $\lambda=0$; at $\lambda=1$ it failed both axes — negative skill and ζ blown to 1.3–2.6 — so the production path is Bayesian graph propagation; the OT term's remaining value is intra-session, where transportability has enough topology to speak.
- *"Why is Layered the default if precision messages scored best?"* The intraday campaign put the static message operator above every layered arm on the ETF triangle (65.8 bp); Layered is the default for its directed and temporal semantics — the schema records that a benchmark-pack adjudication may revisit the default, never the UI ordering.
- *"How wide is the band on a dark node?"* The marginal $1/K^+_{ii}$ — never the diagonal of the precision, which overstates confidence exactly where neighbours are themselves uncertain; the idio floor is a reporting floor on bands, mean-invariant.
- *"Can graph output leak into tomorrow's prior?"* No — the "graph output is never prior input" invariant of `priors.capture_snapshot` holds; the inferred record lives in its own cache.

### Beats 1–9

#### Beat 1 — Implicitation, forward fit and de-Am (≈ 4 min)
- **Path.** `Universe ▾ ▸ Load saved universe ▸ demo-divs` → `Fetch ▾` (as-of rows: `Live · Real-time`, `Prev close`, `Historical · pick a day` with `Close (official)` / `Latest capture · HH:MM` / `n min before close`) → `Snapshot (quotes + spot)` (`POST /fetch/snapshot`; on a streaming Massive book it returns in under a second, the REST path in a few seconds, Cboe up to tens of seconds — the status-bar gauge shows the chain being downloaded and the elapsed time). Open a monthly node (Nodes pane click), Alt+3 (Parametric): the Smile view draws the bid/ask bands of every quote as inverted implied vols with a `LIVE` badge; `Table` lists them with a `C/P` column. `Calibrate` (scope `Parametric only` is enough here: `POST /calibrate/parametric`, an LQD slice is ~13.5 ms, the whole ticker a second or two).
- **Forward / carry.** Alt+2 (Forwards): the ladder `Expiry · T · Parity · Theo · Manual · Active · Borrow · Source` (`GET /forwards/{ticker}`), the forward curve with dividend ex-date markers, and the Forward panel (mode parity · theoretical · manual, `Carry r` / `div q`, the dividend editor with the schedule). Tick **`Joint carry`** (`GET /carry/{ticker}`): the `Joint` and `±σ` columns appear — the joint borrow / de-Am fixed point per expiry; the cell tooltip reads iterations, tree failures and "ATM IV sensitivity … bp per 100bp borrow".
- **Making de-Am visible.** There is no raw-vs-de-Am'd toggle; every quote is inverted through the escrowed-dividend CRR tree (depth 192) at the resolved carry. The honest way to show it: in the Forward panel switch `Dividend model` to `continuous` with `q = 0` (or delete the schedule), **Apply** → the ticker's version bumps; back on the Smile the put and call markers at the same strike split at the money (the "put/call de-Am vol split" the dividends doc names) and the ITM-put side kinks; restore the Cash schedule, Apply, `Calibrate` (or the Spot card's **Recalibrate _ticker_**): the split closes and the fit lands. One line: *"American prices, one European vol per strike — the tree only prices the early-exercise difference, so dividends and borrow are the whole story, and the ladder tells you when parity and theory disagree."*
- **If it fails.** Cboe red / Massive gated → switch the universe source in the market pill (a switch never waits on a feed) or `File ▾ ▸ Open snapshot…`. A `synthesized zero-carry` pill on the Forwards lens = the feed gated NBBO and emitted Black prices at F = spot (parity carries no information) — say so and move on. A gap at the money on the smile = a wrong forward: set that expiry's mode to `Theo` or type a `Manual` level and Apply.

#### Beat 2 — 10-expiry calibration: speed, model comparison, arb control (≈ 5 min)
- **Path.** `Universe ▾ ▸ Load saved universe ▸ demo-core`, `Fetch ▾ ▸ Snapshot`, then `Calibrate` with the scope `▾` on **`Parametric + LV`** (`POST /calibrate`; slices and per-ticker LV fits ship to a process pool). Watch the status bar: the gauge counts nodes (`n/total`), the elapsed bar runs against the client timeout, the **Last** chip reads "Calibrated parametric + LV" with its time. Expect ≈ 4 s for ~30 parametric slices; an LV surface ≈ 1–3 s per ticker on monthlies (the 2026-09-08 graded lattice / BDF2 defaults; a universe with 0–2-day dailies would take 15–25 s and a 300 s LV view timeout exists for that reason).
- **Speed readouts.** The `Fit diagnostics` card (Parametric aside): `ATM vol · Skew · Curvature · RMS — smile · RMS — surface`, Lee slopes and `Var-swap vol` at the expanded size, the model chip with its hyperparameters. Nodes pane rows show RMS bp per node. Alt+5 (Quality, `GET /quality`): tiles `Publish ready · Fitted · Stale · No fit · Arb flags · Median RMS · Worst RMS · LV surfaces`, the per-ticker rollup, the node table sorted `Exceptions first`, the `Wgt` column (five moneyness bands). The LV `Fit diagnostics` card carries the per-expiry table with PDE steps and timings and the ⏵ calibration-trace player.
- **Model comparison.** Parametric ▸ `Compare` (`GET /smiles/{t}/{e}/compare`): the prevailing family (LQD) plus chips for SVI-JW and MCS fitted lazily on the same quotes; columns `RMS bp · Max bp · Tails L/R` and the validity chip (certified / breach / no signal); **`+ reference`** reveals the eSSVI row — a dashed, compare-only yardstick, never a selectable model (a user ruling); the **tail-matching** chip refits SVI-JW/MCS with LQD's tails so the comparison isolates the belly. The Local Vol lens is the fourth model: Alt+4 ▸ `Smile`, then `Compare` for the Dupire twin (the parametric surface differentiated the classical way beside the fitted sheet; round trip, floor and difference sheet — ≈ 0.3 s to build, anchored at the calibration spot).
- **Arbitrage control.** Options ▸ `Calibration` ▸ **`Arbitrage fix`** (= `enforceCalendar`) with `Surface solver` `symmetric` (screen every adjacent pair, joint-repair only the violating runs) — turn it off, Calibrate, and the `Stacked IV` view (total variance w = σ²T per expiry; non-crossing ⇔ no calendar arbitrage) plus Quality's `Cal viol` column show any crossing; turn it back on and only the offending pair moves. `Density` (≥ 0 everywhere — structural for LQD), `Log Q-density` (the LQD backbone), `Densities` across the ladder. The Quality node card is the certificate: `Belly g` (Durrleman on 801 points, rose = uncertified, `·R` = a certified repair), `Lee L/R` (cap 1.95), `Extrap g · cal`, `Tail order`, `Band relax`; the gates (`Tail-order gate`, `As-of mismatch gate`, `Extrapolation guard`) are Options switches, advisory (amber) by default. One line: *"Four families on one screen, one RMS against the same target, and every arbitrage clause certified per node — the export blocks on anything that is not."*
- **If it fails.** A node stays STALE → Calibrate again (edits, Options and forwards all mark stale under the gate). LV `n cal. viol.` badge → say what it measures (adjacent-maturity prices decreased on the PDE lattice) and open the Compare tab. Worst RMS above budget → read the smile for a quarantined quote; click it and press Delete (exclude), Ctrl+Z undoes.

#### Beat 3 — Fit target, quote weighting, var-swap (≈ 4 min)
- **Path.** Options ▸ `Calibration`: **`Fit target`** `Mid | Bid-Ask | Haircut` (the live target is a per-request parameter; the persisted default seeds the session), **`Haircut (vol pts)`** (default 0.005: each side of the band pulled 0.5 vol pt toward mid, never past it), **`Quote weighting`** `equal | uniform_density | tv_density | vega_density | delta_density` (every scheme but `equal` is a TARGET distribution over log-strike reached through the Voronoi strike-density correction, capped 10×, normalized to mean 1). Apply, Calibrate.
- **What to show.** On the Smile, the layer rail at the right of the chart: `Target` (the shaded mid / bid-ask band / haircut band), `Calib. quotes`, `Calib. fit`, **`Weights`** — the strip under the smile on the chart's own x axis (it follows the zoom): the scheme's target shape in grey beside the weight the fit actually sums in accent; hover a bar for `k · target · ×spacing · weight`. Switch `equal` → `vega_density` and Calibrate: the ATM cluster's aggregate weight falls, the 10Δ quotes gain, the wing RMS in Quality moves by a few bp. The Quality `Wgt` column is the same thing pooled into deep put · put · ATM · call · deep call in standardized moneyness.
- **Var-swap.** The `Variance swap` card in the aside (`POST /smiles/{t}/{e}/varswap`): one quote per node seeded at the model's fair level (the log-contract replication of the fitted smile); "Add a var-swap quote at the model level", the `Var-swap vol (%)` input or slider, exclude / remove / undo, the penalty readout (`Var-swap weight (%)` = 15 % of the node's summed quote weights right now), and the **Hard pin** toggle (a stiff 10⁴× row, `pinned` chip, applies on the next refit). Quote it 0.6 vol pt above the fair level, Calibrate: the unquoted wing steepens to supply the variance, the Term view's var-swap curve shows the quote marker, the Fit diagnostics `Var-swap vol` row reads the basis, and the Quality table marks the node `VS`. The Local Vol card prices its own var-swap (`Var-swap pricing` static or `source_pde`).
- One line: *"The target says where each quote must be hit — mid, inside the spread, or inside a trimmed spread; the weighting says how much each quote counts; and a var-swap is one more quote on the tail mass, soft or pinned."*
- **If it fails.** In Bid-Ask the RMS-to-mid rises by design ("zero inside a band") — compare like with like. `Variance-swaps` greyed → Options ▸ Calibration ▸ `Variance-swaps` on. A quote too tight collapses to a mid fit under the haircut (by design).

#### Beat 4 — Event auto-calibration (≈ 3 min)
- **Pick the name.** A name whose forward-variance ladder has a hump inside the demo's horizon. Verify on the day: this week's likely reporters are MU (fiscal Q4, last week of September), COST, ACN, NKE (≈ 30 Sep); in October TSLA / NFLX; NVDA's mid-November print sits inside the Oct-30 → Nov-20 interval of the standing universe. Add the ticker in `Manage universe…`, Fetch, Calibrate.
- **Path.** Alt+3 ▸ `Term` (`POST /term/{ticker}`): the ATM term structure with the clock toggle **`Real time | Event-dilated`**, the forward-variance ladder per interval below, the per-ticker event calendar editor (event time, extra equivalent days, label) and the **`Auto-calibrate events`** button (`POST /events/{ticker}/autocalibrate`): a peak detector — every interval hotter than both neighbours becomes one exactly sized event (floors 0.5 day and 3 %; ramps, backwardation and dips yield none). After the click the result line and `Ladder spread: calendar N bp → event time M bp` sit under the button, and the chart draws BOTH clock readings (the calendar-day reading dashed amber beside the working clock) on either axis — the hot interval pulled down, the vol crush visible. The master switch is Options ▸ `Events` ▸ **`Event variance clock`** (on; `Normalize events` keeps the 1Y budget at 365 days). Prices never move — the clock is a denominator — so the toggle cannot create arbitrage; every fit, the LV grid and the tables read the same clock; de-Am and carry stay on the calendar clock.
- One line: *"Read the event off the term structure instead of smoothing the term structure: one interval hotter than both neighbours is one event of exactly that many days, and the two clocks are drawn side by side."*
- **If it fails.** "Auto-calibrate did not reach the backend — calendar unchanged" → the backend is down; the calendar can be typed by hand (event date + extra days) and Applied. No event found → the ladder is a ramp or the hump straddles two intervals (a plateau is invisible by design); pick another name.

#### Beat 5 — Spot-vol dynamics with ticking spot and quotes (≈ 4 min)
- **Setting.** Options ▸ `Dynamics` ▸ **`Spot-vol dynamics regime`** `Mny | Strike | LV | LV grid | SSR` (sticky moneyness R=0, sticky strike R=1, sticky local-vol R≈2 Hagan map, the exact frozen-grid Dupire reprice with the realized SSR reported, custom with **`SSR value`**). Display-only: applied at read time to the cached anchor, so switching regimes refreshes every view instantly and busts nothing. Workflow ▸ **`Auto-update`** `Off | Spot only | Spot + quotes` with `Every (s)` (15 s floor for snapshots; a spot update only transports, never refits) — inert while a book streams; **`Stream live book (Massive / Bloomberg)`** opens the push book (the market pill shows the streaming badge), `Stream refit every (s)` (with Auto-calibrate on) and `Freeze fit while streaming`.
- **Path, market open (14:30–21:00 London = 09:30–16:00 New York).** Universe source Massive, `Stream live book` on: the `Spot move` card in the aside shows `Calibrated · Market · Scenario`, the **`Follow: Market spot | Scenario`** selector and `Regime · R`; with `Market spot` followed the market spot streams off the book at ~1 Hz and the surface transports live under the regime — nothing refits (the quotes and spot on the Massive delayed tier are ≈ 15 min behind, say so). The node's tick stream (one SSE per viewed node, `GET /smiles/{t}/{e}/table/stream`) flashes the `Table` cells and rolls the market frame at ~1 Hz. Switch `Strike` → `Mny` → `LV` in Options while a tick lands: the same move re-labels the smile differently (on a −0.35 skew and a −5 % move, sticky-strike lifts ATM ≈ 1.8 vol pt, sticky-moneyness 0, sticky-local-vol ≈ 3.5).
- **Path, market closed (the safe path at any hour).** Select `Scenario` in the Spot move card: the dial (`±0.1 %` buttons, Shift = 1 %, `Reset to 0.0%`, `Sync to market`; `PUT /spot/{ticker}`) transports every lens live — the Parametric smile, the Local Vol smile and surface (the nodal grid relabels x → x·e^{−(R/2)h}), the term structure, the strike brush. **`Recalibrate _ticker_ (_scope_)`** is the top-bar Calibrate for that one ticker (`POST /spot/{ticker}/calibrate`) at the scenario's own snapshot rule; the old fit stays until the new one lands. The Synthetic source is deterministic (a fixed spot per ticker) — it does not tick; the dial is the demo.
- One line: *"Between two calibrations the surface is a function of spot under a stated regime; the regime is a dial with the classic rules as marks, and the delta of one OTM put moves by 20 delta points between R = 0 and R = 2 — that is a hedge, not a display choice."*
- **If it fails.** Book "warming" / no ticks → the dial. Chart frozen under a stream → `Freeze fit while streaming` is on (status bar "Stream · frozen"). The dial "does nothing" → `Follow` is on `Market spot`; select `Scenario`.

#### Beat 6 — Persistence on an illiquid underlier (≈ 4 min)
- **Which name.** The prior's effect is visible where today's quotes do not identify the wing: a single name with a sparse chain and wide spreads — a mid-cap or a thin long-dated expiry of a large name (AAPL / NVDA Jun-27 quarterly shows it; a small-cap with 8–12 strikes shows it better). Prepare it in `demo-core` the night before so its prior is saved and fresh (Priors ▾ ▸ `Save priors — all calibrated`, `POST /priors/save-all`; one prior per node, active on save, per fit target).
- **Path.** Options ▸ `Prior` ▸ **`Prior persistence`** `Off | Overlay only | Strike gaps | Quote operators | Smile factors | Hybrid | Graph only` (Hybrid = level-invariant operators ATM / RR25 / BF25 / VarSwap gap-gated by today's quote support + a deep-tail strike anchor at 2/5/10Δ; `Operator strength (%)` 50, `Tail-anchor weight (%)` 20, `Two-pass (don't damp signal)`, `Var-swap carrier` Absolute level / ATM spread, `Wing slope scale` for the WingL / WingR operators). Apply, Calibrate. On the Smile: the dashed transported prior and the solid fit coincide in the unquoted wing and separate where quotes exist.
- **The anchoring axis.** On the Smile / Density views the **Fit switch `Free · + Prior · + Filter`** draws one shadow fit of the selected node in place of production (`anchoring=` on the smile / density / compare routes; read-only, no cache entry, no filter update); on `Compare` the same three chips add the `Pull` column (what each block bought on this node in bp). `+ Prior` is a preview whenever a prior node exists — even with the mode Off. Flip `Free ↔ + Prior` on the thin expiry: the 2Δ put wing swings between the model's own Lee-bounded extrapolation and yesterday's shape.
- **The diagnostics table.** Options ▸ `Prior` ▸ the panel's **`Config | Evidence`** tabs and the table `Expiry · Factor · gap · λ · age · src · h` (`GET /smiles/{t}/{e}/prior-diagnostics`): `gap` 1 = fully persisted, 0 = the data wins; `λ` the final weight; `age` in days; `src` active / nearest / bootstrap / flat; `h` the transport distance. Read it aloud: gap ≈ 0 on ATM, ≈ 1 on the wing rows is the intended picture; a well-observed coordinate gets exactly zero prior weight. `Priors ▾ ▸ Fetch priors` (`POST /priors/fetch`) only re-reads and seeds tickers that have none (from the previous close).
- One line: *"The prior is admitted exactly where today's likelihood is flat and nowhere else — and the table lists every persisted quantity with its weight, so it is never a hidden stabiliser."*
- **If it fails.** `+ Prior` greyed → no prior node for that expiry: save one (`Priors ▾ ▸ Save prior — visible tab`) or check `Fetch priors` (fits and saves are per fit target — a haircut session needs priors saved under haircut). Prior age reads 97 days → step 4 of the pre-flight was skipped; the transported prior is still drawn, with a large `h`.

#### Beat 7 — Kalman filtering and tail persistence, with and without (≈ 6 min)
- **Path.** The Series lens is the cinematics: one ticker, ordered instants (frames), several settings lanes evaluated through time — a lane with a prior reads its own previous frame, a lane with the filter carries its own state. Open an NVDA node tab, Alt+6 (Series; needs VOLFIT_DB), **`New series…`**: `Historical` (harvested now through Massive's as-of path: per-contract NBBO history, nearest-the-money first, `NBBO_MAX_CONTRACTS` = 1,500 ≈ 12 s per frame on NVDA), `Step` / `Count` / `Start (blank = the latest instants)` / `Warm-up frames`, `Ladder` pinned with `Max expiries` 3–4 (a short ladder keeps every frame under the contract cap and the fits under a second), `Fit target` haircut, `Frame budget (s)` 300, lane presets `LQD-24 free` · `LQD-24 + prior` · `LQD-24 + prior + filter` · `SVI-JW free` · `MCS free` · `LV affine free` · `LV affine + prior` · `Current Options`, one starred as the production lane. **Estimate** first (instants, servability, harvest and calibration time, amber warnings), then **Start** (`POST /series`, `/series/{id}/start`; the harvest and the lane fits run on two threads — the first smile lands after one fetch, the pill reads "Harvesting NVDA frame 4/10 · Calibrating frame 2/10 · lane").
- **Two series to prepare.** (a) *Intraday*: step 5 min × 12 frames, lanes `LQD-24 free`, `LQD-24 + prior`, `Current Options` with the live filter set to **Overlay only** — the `+ prior + filter` preset means the ACTIVE filter and the dialog warns for any active-filter lane on a sub-day series: on the first desk day (2026-09-11) that lane went 1.6 → 1,033 s per frame with rms 7.9 → 161 bp and held the series at 8/10; the MAP block's predicted variances collapse on one-day rungs. - **Replay.** Stages `Smile · Frames · Surface · Term · Lanes`; the transport bar (Space play/pause, ← / → one frame, Shift+← / → ten, Home / End, L loop, 0.25×–8×), the filmstrip sparklines (spot, ATM per lane, fit error per lane), the ghost trail of the production lane, the playhead naming the instant and the quote kind (NBBO vs marks). **`Lanes`** = the evidence: metric chart `rms bp · max error · pull ATM · ζ ATM · fit ms · ATM σ · skew · curvature` across frames, the summary table `Lane · Frames · Mean rms bp · Mean max bp · Worst frame · handle-path roughness · mean |pull| · ζ std · fit ms` (best value lit), and for a filter lane its **ring** for a chosen expiry and handle with the playhead as cursor (prediction and observation bands, the posterior, the ζ strip, the gain). The measured line to quote: on a 1-day rung at 15 min the hybrid prior damps roughness 18.4 → 17.5 bp/frame for +0.5 bp rms.
- **Tail persistence** = the wing carriers of Hybrid: the deep-tail anchor below the shallowest wing operator, the `WingL / WingR` slope operators (`Wing slope scale`), the `Var-swap carrier = ATM spread` so a level move carries the tail along, and `Wings survive an active filter` (the Note 15 §6.3 carve-out: the wing rows persist beside the Kalman MAP rows, which own the body). Show it on the daily series: free lane's 2Δ wing wanders frame to frame; the + prior lane's holds.
- **FilterTimeline on the live desk.** Options ▸ `Kalman filter` ▸ `Observation filter = Overlay only`, the diagnostics table `K(ATM) · K(skew) · K(curv) · innov bp · ρ · route · reset · ⚠` and the **Timeline** toggle (prediction / observation bands, posterior, ζ strip, gain, Q breakdown, reset markers; `Live | Replay` source chip); the Smile gains a `FILTER` badge (gains per handle, ρ; amber = contaminated measurement). - One line: *"Noise is not a gap: the filter denoises through time with a gain it computes from the fit's own information, the prior fills what today's quotes cannot see — and the lanes let you watch the three histories side by side on the same frames."*
- **If it fails.** Series empty state → the server has no store (`VOLFIT_DB`) — reopen the exported `.volfit-series.json`. A lane at 8/10 → the frame budget moved on (the lane keeps its slice fits; the run continues). A day tagged `marks` (bid = ask, hollow diamonds) → the key hit its history entitlement or rate limit for that instant; the lanes still fit, say so. Massive history more than a few sessions back is unverified on this key (2026-09-10 verified two days back) — keep the daily series inside the last two weeks and run it the night before.

Skill exactly 0 → topology, not damping (check the `Relations` tab). The reveal is attribution, not chronology — do not narrate it as a cascade.

**Does the interpolation make any sense in LV?** Short answer: the graph never interpolates in local-variance space, and the app is deliberate about that. The solve lives in the three ATM handles (level, skew, curvature) of the parametric smiles; a dark node's transported prior smile is retargeted to the posterior handles with its wings intact (`graph_reconstruct`), and `graph_extrapolation.py` has no affine code path at all. Local vol is not transported node to node because an LV surface is a joint surface-level object — "LV calibration is a full surface optimisation, not a parameter mutation" (`api/graph_lv.py`). What exists instead is a **projection**: the Local Vol lens's **`Graph-extrapolated`** button (`POST /graph/extrapolate/lv/{ticker}`) re-runs the standard affine calibration with each expiry's target total variance replaced by the graph-reconstructed smile sampled on that expiry's live strikes (band → none, so it targets the extrapolated mid; expiries without a chain keep their live row). The result IS arbitrage-consistent in the sense that matters: a positive piecewise-affine local-variance sheet priced through the Dupire forward PDE keeps the density ≥ 0 and adjacent-maturity prices ordered on the lattice, and the toolbar's `arb-free` / `n cal. viol.` badge reads that lattice. What is not guaranteed is consistency among the targets — the per-node retargeting has no hard calendar clause, so where two inferred smiles cross in total variance the sheet absorbs it as misfit (a reason to look at `rms · conv · max` on the projection). Nothing else in the Local Vol lens changes after a Run; the projection is labelled violet as a projection of reconstructed smiles, not of quotes, and it costs an LV fit (1–25 s per surface). Two neighbours worth naming if asked: `api/prior_lv.py` is the PRIOR path, not the graph — yesterday's operator / factor prior enters the LV fit as signed price-basket rows with frozen-vega weights, and a saved prior carries its LV surface; and `api/affine_transport.py` moves the calibrated sheet with spot (the grid relabels x_i → x_i·e^{−(R/2)h}, local vols unchanged). Recommended line for the presenter: *"The graph interpolates and extrapolates smiles, in handle space, along calendar and cross-asset edges — that is where the information is. Local vol is what those smiles imply through Dupire, so for a dark expiry we project the inferred smile onto the local-vol sheet, arbitrage-free by construction, and we label it as a projection. We do not interpolate local variance across nodes, and we would distrust anyone who did — the Compare tab is there to show what differentiating a surface versus fitting one actually costs."*

## 10. Data fetch and live streaming — what is done, the limitations, what to do instead

Reviewed 2026-09-23 after the US close (about 23:35 London), on the code at commit `4e5f8a9` (the SPX fix included), with read-only probes of the running app, live calls to Massive and to the Bloomberg Terminal (which answered green all evening), and the vendor pages. The two raw reviews with every `file:line` and vendor URL are `Docs/deck/prep_2026-09-23/fetch_review.md` and `stream_review.md`; the probe scripts `fetch_*.py` / `stream_*.py` sit beside them. Vendor limits are marked **[vendor doc]** when a page states them and **[unverified]** otherwise.

### 10.1 What is currently done — fetching a chain

**Massive REST (`data/massive.py`).** One pooled `httpx` client (HTTP/1.1, keep-alive, 15 s timeout) serves every call. A chain fetch is three things: the **contract listing** (`/v3/reference/options/contracts`, 1,000 rows per page, SPY = 13 pages ≈ 1.4 s, cached per ticker for the life of the process — and pulled a second time under another cache key for the websocket / as-of contract set); the **snapshot**, one query per selected expiry (`/v3/snapshot/options/{U}?expiration_date=…&limit=250`, the documented page maximum **[vendor doc]**), paginated serially inside an expiry and run two expiries wide (three or four measured slower, eight hit read-timeouts on the delayed tier; a whole-horizon fetch with no expiry selection is one fully serial stream); and the **spot** from the snapshot's underlying price, else parity on the front expiry, else the stocks snapshot. When a websocket book is live, a "live" fetch reads the book and makes **no REST call** (the first fetch after a stream starts still goes to REST because the book cannot imply a forward yet). The status light costs two GETs per probe, re-probed every 30 s while the selector is open (≈ 240 calls per hour idle). Nothing above the provider caches Massive chains: `POST /fetch/snapshot` accepts `maxAgeSeconds` but only the MCP connector sends it; the UI's Fetch never does.

**Massive history — the as-of path (`data/massive_history.py`).** A past instant is rebuilt **per contract**: the listing, one synchronous probe quote, a spot hint (two calls), then up to 1,500 calls to `/v3/quotes/{contract}?timestamp.lte=…&limit=1`, twelve in flight, nearest-the-money first (`|ln(K/S)|/√T`). There is **no retry**: one `NOT_AUTHORIZED` or one rate-limit body raises, sets a session-wide gate, and every later past chain is served as marks (bid = ask) until the server restarts. The store is never consulted first: the Series lens saves every harvested frame as a snapshot row, but the Smile lens's as-of view rebuilds the same instant again from 1,500 calls.

**Flat files.** The app's `FlatFileStore` reads minute / day aggregates (marks only) through DuckDB, filtering one whole day file to the watchlist. The two-sided `quotes_v1` product is one unsplittable gzip per day, 111 GB for one day, 4.8–8.85 h per scan — the backtest's overnight tool, not an interactive path **[vendor doc: "a daily downloadable S3 file"]**.

**Bloomberg (`data/bloomberg*.py`).** One xbbg session for `bdp`/`bds`/`bdh`, a second for symbol search, a third on a daemon thread for `//blp/mktdata`. The chain listing is three bulk requests (`OPT_CHAIN` for monthlies/LEAPS, `CHAIN_TICKERS` with the W and Q periodicity overrides, `EXP_DT=ALL`, puts mirrored, the yellow key appended), cached 600 s. Quotes are one `PX_LAST` for spot, a uniform strike window of 0.5–1.5 × spot, then **one `bdp` over every selected contract with six fields** (BID, ASK, LAST_PRICE, VOLUME, OPEN_INT, OPT_EXER_TYP); blpapi splits it internally into groups of 10 securities × 128 fields **[vendor doc]**. While the Bloomberg stream is up, `fetch_chain` and `spot()` never call `bdp`. History is one `bdh` per date over all contracts. The status light is quota-free (session state plus the last refusal recorded), which is why it can read "workflow review needed" hours after the Terminal has recovered — it did today, while `bdp` answered 767.81 and four subscriptions painted in under 8 s.

**Others.** Cboe = one CDN JSON per underlying (SPY 6 MB ≈ 0.8 s, SPX 14 MB ≈ 1.2 s, no key, 60 s TTL); Nasdaq one JSON per asset class (≈ 1.5 s, flaky); Yahoo one yfinance call per expiry (≈ 2.7 s a ladder, one-sided after hours).

### 10.2 What is currently done — the live stream

**Lifecycle.** `OptionsSettings.autoStream` (default on) opens a book. The scheduler thread wakes every second and, for every provider that can stream (Massive, Bloomberg), streams it iff at least one active ticker is served by it; the desired contract set is rebuilt every tick and applied as an incremental subscribe / unsubscribe diff. A stream stops when its provider serves no ticker; a server restart starts from an empty book. The socket is one daemon thread per provider **inside the API process** (the calibration pool never sees the book; it receives chain snapshots).

**The subscription set.** Massive: `option_tickers` returns **every listed contract of the selected expiries** — calls and puts, all strikes — and the client sends the auth frame and then **one subscribe frame** naming `Q.O:…` per contract: no window, no chunking, no cap, no wildcard. Counted today from the reference listing (no socket opened): the running app's SPY selection = 26 expiries = **10,560 contracts** (a 237 KB frame), NVDA = 9 expiries = **1,866**, SPX's full ladder would be **30,388**. Bloomberg is windowed by design: strikes within 0.5–1.5 × spot around a centre held with 5 % hysteresis, the underlyings prepended, capped nearest-the-money at 3,000 (`VOLFIT_BBG_MAX_SUBS`), subscribed in batches of 200 with `interval=1` conflation; over-cap contracts are carried unquoted and counted in the light.

**Data path and cadences.** A frame is parsed into a `LiveBook` = `{contract → last (bid, ask, ts)}` — last tick only, no ring, no counters; the only status handling flips `connected` on `auth_success`, and any `status: "error"` frame is **dropped silently**. Reads: a live fetch builds the chain from the book (every quote stamped with its own tick time, spot = the book's parity forward; `None` until enough two-sided pairs exist, then REST). While a book streams the scheduler moves market-following tickers to the book spot every 5 s (a transport, never a refit) and, with Auto-calibrate on, refits every `streamRefitSeconds` (5 s) off the book; `Freeze fit while streaming` holds both; `autoUpdate` is inert for streaming tickers. Each viewed node opens one Server-Sent-Events connection that polls the book at 1 Hz and pushes strike-keyed deltas. The pill: "stream warming" = no stamped tick yet, "streaming" = newest tick ≤ 20 min old, else "stream idle since HH:MM". Persistence: **nothing of the stream is recorded**; a live Series stores one cropped chain per frame off the book, historical series go through the 12-s REST as-of path; a live session cannot be replayed from ticks afterwards.

### 10.3 Limitations — the direct answers

**Number of tickers / size of the streamed universe.** The binding limit is the vendor's, not the machine's. Massive: *"You're only allowed to subscribe to 1,000 option contracts per connection"* on the quotes feed **[vendor doc]**, the refusal is per message and all-or-nothing (a frame that would cross the cap is rejected in full: *"Subscription limit reached for feed. Please remove some subscriptions and try again."*), the count is cumulative on the connection, and paid plans get **one connection per cluster** (Business three; a second `/options` connection is refused with *"Maximum number of websocket connections exceeded"*) **[vendor KB]**. The app sends 1,866–10,560 contracts in one frame and ignores the answer. The evidence that this is what is happening right now: the server has been up since 09-18 through four US sessions with NVDA pinned to Massive, and at 23:35 the pill reads "delayed feed · stream warming", the scheduler says `streaming: true`, the NVDA SSE status frame says `ready: false`, and `/spot/NVDA` still carries the REST probe of 09-18 14:09 as its live spot — **the book has never served a quote**. On the current design anything beyond about three SPY expiries or five NVDA expiries cannot stream at all, SPX is out of the question, and a 25-ticker universe would be 40 contracts per ticker. Bloomberg: the documented figure is 3,500 real-time fields open at once for the Terminal **[library guide, unverified as vendor-official]**; the BLPAPI guide only says a concurrent-subscription limit exists; the app's own cap of 3,000 (2,998 subscribed on the 2026-08-20 smoke, zero metered calls) is the safe number. CPU is not the constraint: parse + book apply measured at 264k–473k events per second, a full SPY book-to-chain read 42 ms, an estimated 1–10k events per second at the 1,000-contract cap near the money — 25–250× under the ceiling.

**Time span of a continuous stream.** No hard bound in code: capped reconnect backoff 1 → 30 s, a ping every 20 s, unlimited frame size, book memory = the subscribed set (1.7 MB for 10,560 contracts, no growth over time). What degrades a long run: (a) the 6-s "silent cluster" rule — a fresh session with no quote within 6 s rotates to the next candidate URL, and with `VOLFIT_MASSIVE_WS_URL` set the candidate list is that one delayed host, so every quiet spell (the whole night, or a refused subscription) becomes a reconnect every 6–36 s, about 2,400 connections a day, with no log line anywhere; (b) the Massive ladder and contract caches are never invalidated across the ET day roll (`refresh_contracts` has no caller), so a server running across days keeps yesterday's expired rung in its ladder and never learns a newly listed expiry until restart; (c) a dead websocket thread is restarted every tick with a new empty book, invisibly; (d) overnight the book keeps the last ticks, so a "live" fetch is stamped hours old and readiness fails on data age by design (red past 120 min). Vendor idle-disconnect rules are not documented **[unverified]**, and whether the delayed cluster's `t` is the SIP time or the delivery time is not stated. No multi-day continuous stream with a served book is recorded anywhere; the current five-day run is the first, and it never served.

**Robustness.** There is no stream-health surface at all — no message counter, last-message age, reconnect count, acknowledgement or refusal text; `is_streaming(ticker)` means "the thread is alive", so a refused subscription still marks the ticker as streaming, keeps `autoUpdate` inert for it, and holds the SSE at "warming" forever. Bloomberg's light shows the last reference refusal until the next real fetch, even while `bdp` answers and `//blp/mktdata` streams.

**Fetch latency and throttle.** Massive's cost is pages × ≈ 0.1 s at 250 rows per page, inflated by per-expiry queries that leave the last page of every expiry partly empty and by the fully serial whole-horizon stream; the 1.4-s listing is paid per ticker per process, twice. The snapshot endpoint visibly resists concurrency beyond two (measured, not documented); responses carry no rate-limit headers; the app neither counts calls nor retries, and one rate-limit body on the history path degrades the whole session to marks. Bloomberg's cost is server-side (5–16 s per `bdp`, 70–200 securities per second) and metered: 500,000 hits per day (security × field) and a monthly budget of unique securities that Bloomberg "recommends" at 4,000–5,000 **[library sheets, unverified]**. Six fields per security multiply the daily hits by six when only BID/ASK feed the fit, the uniform 0.5–1.5 × spot window keeps thousands of unique securities per fetch (a 2-day rung needs ± 5 %), and one SPX chain spends ≈ 20k unique securities in a single call — four times the recommended monthly budget, consistent with both recorded gates (`DAILY_CAPACITY_REACHED` 2026-06-15, `WORKFLOW_REVIEW_NEEDED` 2026-09-10 after 7.8k + 20k-contract pulls).
