# Live streaming review — universe size, time span, vendor limits, what to do instead

Reviewed 2026-09-23, after the 09-23 US close (about 23:35 London / 22:35 UTC). Paths are under `backend/volfit/` unless noted. "Measured" = run today (scripts beside this file); "vendor" = the cited page; "estimate" / "unverified" are labelled as such.

## What is currently done

**Lifecycle.** One setting opens a book: `OptionsSettings.autoStream` (default ON, `api/schemas.py:827`). The scheduler thread wakes every second (`TICK_SECONDS = 1.0`, `api/scheduler.py:38`) and calls `AppState.sync_streaming()` (`scheduler.py:110`). That method (`api/state_sources.py:95-134`) walks every registered provider exposing `start_streaming` (Massive, Bloomberg) and streams it iff `autoStream` is on and at least one active ticker is served by it — pinned to it or following it as the default source (`tickers_of`, `:51-54`). The desired contract set is rebuilt every tick from `prov.option_tickers(ticker, selected_expiries)` (`:136-146`); a change is applied incrementally by `update_streaming` (Massive `data/massive.py:494-510`, Bloomberg `data/bloomberg_live.py:151-170`), no reconnect. A stream stops when its provider serves no ticker (`state_sources.py:116-117`): a source switch, an unpin, `autoStream` off, an emptied universe. A server restart starts from an empty book. Bloomberg is registered with `interval=1.0` conflation and a 3,000-subscription cap (`serve.py:103-104`; env `VOLFIT_BBG_STREAM_INTERVAL`, `VOLFIT_BBG_MAX_SUBS`).

**Who owns the socket.** One daemon thread per provider, inside the API process: `MassiveWebSocket` runs an asyncio client on thread `massive-ws` (`data/massive_ws.py:163-168, 219-223`); Bloomberg runs a blpapi session on thread `bbg-mktdata` (`data/bloomberg_stream.py:237-242, 362-374`). uvicorn runs one process (`serve.py:293`); the calibration pool is a spawn-context `ProcessPoolExecutor` for slice / LV fits only (`api/fit_pool.py` docstring) — the workers never see the book; they receive chain snapshots.

**Subscription set — Massive.** `option_tickers` (`massive.py:456-459`) returns EVERY listed contract of the selected expiries — calls and puts, all strikes (`_intraday_contracts`, `:922-960`: the reference endpoint with `expired=false`, cached per `(ticker, frozenset(expiries))`). The client sends the auth frame and then ONE subscribe frame naming `Q.O:…` per contract (`massive_ws.py:250-251, 266-269`): no chunking, no wildcard, no cap. Measured today (`stream_count.py`: REST reference listing only, no socket opened):

| Ticker | Full ladder | The app's selection | Subscribe frame |
|---|---|---|---|
| SPY | 12,206 contracts / 32 expiries (6,103 C + 6,103 P) | 26 expiries → **10,560** (282–638 per expiry) | 237 KB |
| NVDA | 3,838 / 23 expiries | 9 expiries → **1,866** (152–494 per expiry) | 44 KB |
| SPX | **30,388** / 58 expiries | not in the universe | — |

**Subscription set — Bloomberg.** The plan is windowed: contracts inside `strike_window` (0.5–1.5 × spot) around a centre held with 5 % hysteresis (`RECENTER_PCT`, `bloomberg_live.py:42, 71-92`), the underlyings prepended (spot comes off the stream), capped nearest-the-money first at `max_subscriptions` (`_cap`, `:171-193`); over-cap contracts are carried unquoted and counted in the light ("N over cap", `:258-262`). Subscriptions go in batches of 200 (`SUBSCRIBE_BATCH`, `bloomberg_stream.py:52`). Planning needs two metered reference calls per ticker — the chain listing (`OPT_CHAIN` + `CHAIN_TICKERS`) and one `PX_LAST` to centre the window (`Docs/bloomberg_setup.md`, "Real-time streaming").

**Expired / newly listed expiries.** At the ET day change the scheduler rolls `reference_date` (`scheduler.py:99-107`; `AppState.roll_reference_date`, `api/state.py:611-651`): auto expiry selections are cleared and re-resolved, custom ones drop dates ≤ today, and the next tick's `sync_streaming` diff unsubscribes yesterday's rung and subscribes the new one. But the Massive provider's ladder and contract caches are never invalidated in-process: `refresh_contracts` (`massive.py:962-965`) has no caller (grep), and `available_expiries` filters by `date.today()` only when it fills its cache (`:299-318`). A server running across days re-resolves from a ladder that still holds the expired date and never learns a newly listed expiry until restart.

**Data path.** A text frame → `_parse` (`massive_ws.py:312-321`) → `LiveBook.apply` (`:60-73`). The book is `{contract → QuoteTick(bid, ask, ts)}`: the last tick only, no ring, no counters; the only status handling flips `connected` on `auth_success` / `success` — any `status: "error"` frame is dropped silently (`:72-73`). Reads: `fetch_chain(live)` serves `_chain_from_book` (`massive.py:641-644, 547-593`): every quote is stamped with its provider tick time (`_ns_to_utc_naive`, `:77-85`), the chain with the newest of them, the spot is the book's parity forward (`_spot_from_quotes`, `:535-545`); the read returns `None` until enough call/put pairs are two-sided and `fetch_chain` then falls back to a REST snapshot. `book_spot` (`:327-334`) is the nearest expiry's parity forward. Bloomberg mirrors this (`bloomberg_live.py:214-268`) with the underlying's LAST / mid as spot and un-stamped INITPAINT quotes capped at the chain's newest stamp.

**Cadences.** While a book streams, the scheduler moves market-following tickers to the book spot every `STREAM_SYNC_SECONDS = 5` (`scheduler.py:41, 122-124`; `api/workflow_spot.py:53-70` — a transport, never a refit) and, with `autoCalibrate` on, runs `workflow.stream_refit` every `streamRefitSeconds` (5 s default, `schemas.py:814`; `api/workflow.py:348-380`: `refresh_chain` off the book — `state.py:1238-1254` — then `calibrate_all` in the background, skipped while a job runs). `streamFreezeFit` (`schemas.py:819`) holds both (`scheduler.py:115`). `autoUpdate` is inert for streaming tickers (`scheduler.py:130-131`). The Quote Table / Smile Chart open ONE Server-Sent-Events connection per VIEWED node (`GET /smiles/{t}/{e}/table/stream`, `routers/smiles.py:211`; `frontend/src/state/useLiveTicks.ts:9-12`, opened only while visible): `table_events` polls `live_chain` (book-only) at 1 Hz with a 15-s keep-alive and pushes strike-keyed deltas (`api/table_stream.py:347-390`). The pill reads `feed_status` every 30 s (`frontend/src/state/useDataSources.ts:52`; `api/datasource.py:46`): "stream warming" = the book has no stamped tick, "streaming" = newest tick ≤ 20 min old, else "stream idle since HH:MM" (`massive.py:239-252`).

**Persistence.** Nothing of the stream is recorded. The store holds chain snapshots, fits, priors (`data/store.py:64-150`). A Series in `live` mode stores one cropped chain per frame through `state.refresh_chain` — the book when the ticker streams (`api/series_harvest.py:39-49, 74-78`); historical series go through the REST as-of path (`massive_history`, about 12–14 s per chain). A live session cannot be replayed afterwards from ticks.

## Limitations

**1. The vendor caps the options quotes channel at about 1,000 contracts per connection; the app subscribes 1,866–10,560.** Vendor: "You're only allowed to subscribe to 1,000 option contracts per connection" (docs, options quotes); "The refusal is per message and all or nothing: a message that would cross the cap is rejected in full … the count is cumulative across messages on that connection", the error text being "Subscription limit reached for feed. Please remove some subscriptions and try again." (knowledge base). The app sends one frame with the whole set, ignores the error status and never logs. Evidence that this is live today: the server (PID 25520) has been up since 09-18 14:56 London, through four US sessions, with NVDA pinned to Massive; at 23:35 after the close `/datasources` says "delayed feed · stream warming", `/scheduler` says `streaming: true`, the NVDA SSE status frame is `streaming: true, ready: false`, and `/spot/NVDA` still carries the REST probe of 09-18 14:09 UTC as its live spot — the book has never served a quote. (When the pin was set is not readable without mutating the app; the 2026-06-15 verification that "streams live SPY NBBO" recorded no contract count, ROADMAP 10599-10616.) Consequence: any selection beyond about 3 SPY expiries or 5 NVDA expiries cannot stream at all on the current design; SPX (30k) is out of the question.

**2. Number of tickers / universe size.** With the cap, the binding budget is 1,000 contracts per connection and one connection per cluster per paid plan (Business: 3, up to 5 free); on `/options` a second connection is REFUSED with "Maximum number of websocket connections exceeded" (knowledge base) — so no diagnostic script, recorder or second app instance can share the key while the app streams. The code has no notion of the budget for Massive; Bloomberg has one (3,000, self-imposed). The Terminal's documented figure is "no more than 3500 real time fields open at the same time" (Columbia library guide — the Terminal / Excel add-in); the BLPAPI guide only states that a "concurrent subscription limit" exists (`SubscriptionTerminated`, p73) — the DAPI number is unverified. Measured Bloomberg smoke 2026-08-20: SPY + SPX, 2 expiries each, 3,166 wanted → 2,998 subscribed, 0 metered calls (`Docs/bloomberg_setup.md`).

**3. Time span.** No hard bound in code: capped backoff 1 → 30 s, `ping_interval=20`, unlimited frame size (`massive_ws.py:143, 244-247, 309`); Bloomberg auto-restart + backoff (`bloomberg_stream.py:282-296, 370`). Book memory is the subscribed set only (measured 1.7 MB for 10,560 ticks, 2.2 MB for 12,206), with no growth over time. What does bound a long run: (a) the 6-s silent-cluster rule (`quote_grace`, `massive_ws.py:144, 275-299`): a fresh session with no quote within 6 s is judged "silent", the client rotates candidates and, with `VOLFIT_MASSIVE_WS_URL` set to the delayed host, the candidate list is ONE URL (`_ws_urls`, `massive.py:466-480`; measured `['wss://delayed.polygon.io/options']`), so every quiet spell after a drop — the whole night, or a refused subscription — becomes a reconnect every 6 s + backoff (≤ 36 s): about 2,400 connections a day, no log line anywhere (`massive_ws.py` has no logger; `_run` swallows everything, `:219-223`); (b) the stale contract / ladder caches across the day roll (above); (c) a dead WS thread is restarted every tick with a NEW empty book (`massive.py:487-492`), invisibly; (d) the delayed cluster's stamps put the data age at ≥ 15 min (under the 20-min amber, `dataAgeAmberMin`), and overnight the book keeps the last ticks, so a "live" fetch is honestly stamped hours old → red past 120 min → readiness fails with "stale data" (`api/data_age.py`). Whether the delayed feed's `t` is the SIP time or the delayed-delivery time is not stated by the docs ("The Timestamp in Unix MS") — unverified. Vendor idle-disconnect rules: not documented. No multi-day continuous stream with a served book is recorded anywhere (ROADMAP / memory grep); the current 5-day run is the first, and it never served.

**4. Robustness gaps.** There is no stream-health surface: no message counter, last-message age, reconnect count, ack / refusal, or vendor error text; `is_streaming()` means "thread alive" (`massive.py:519-520`), so a refused subscription still marks the ticker as streaming, keeps `autoUpdate` inert for it and holds the SSE at "warming" forever. The socket shares the API process's GIL with inline fits (interactive and autoCalibrate-on-GET fits run inline, `fit_pool.py` docstring); the parse headroom is large (below), and a long inline fit stalls the book READS, not the socket (asyncio buffers). Bloomberg: the light shows the last reference refusal ("workflow review needed") until the next real fetch (`data/bloomberg.py:326-356`) even when `bdp` answers (it does today: PX_LAST 767.81) and `//blp/mktdata` streams; and the stream cannot be planned while the two metered listing calls are refused.

## What can be done instead

| # | Proposal | Effect | Constraint / citation | Risk | Effort |
|---|---|---|---|---|---|
| 1 | Subscribe the fitter's strike window, nearest-the-money first, ≤ 950 per connection; chunked frames; parse `status: error` | Streaming works at all; NVDA's 9 expiries at about 100 near-money contracts each | vendor cap 1,000 per connection; port `_window_contracts` + `_cap` from `bloomberg_live.py` | wings unstreamed → pair with 3 | S–M |
| 2 | A stream-health model + an honest pill: messages/s, last-message age, reconnects, acked / refused counts, the vendor error text; `is_streaming(ticker)` = "book acknowledged", else the request path | The 5-day silent failure becomes a red light within 30 s; `autoUpdate` stays live on a dead stream | `massive_ws.py:72-73` drops errors; `massive.py:519` = thread alive | none | S |
| 3 | Tiered rates: the viewed node(s) at full NBBO within the cap, the rest on `AM.` per-minute bars or REST snapshots at the Auto-update cadence; re-plan when the viewed node changes | The whole universe live at the right granularity | `AM.` has no stated cap; its wildcard only on Business Full Market; the SSE open/close already names the viewed node | bars are marks, not NBBO | M |
| 4 | More connections: one socket per group of ≤ 950 contracts | N × 1,000 contracts | one per cluster per plan; Business 3 (+2 free); extra options connections on request to Massive | commercial | S code |
| 5 | A tick-recorder / streaming service outside the API process writing 1-s book snapshots (or raw ticks) to SQLite / parquet; the API reads the book locally | Survives restarts; replayable Series frames without the 12-s REST harvest; GIL isolation | the one-connection rule: the API must not also connect | an ops surface | L |
| 6 | Day-roll hygiene: `refresh_contracts()` at the ET roll, drop expired contracts, add the new rung, a 09:25 ET re-plan | A correct ladder across days | no caller today; `state.py:611-651` | none | S |
| 7 | A session-clock-aware silence rule + a heartbeat stale rule | No overnight reconnect storm; "idle" keyed on the last message age | `quote_grace` 6 s; `expiry_time.ET` | none | S |
| 8 | Bloomberg: keep `interval=1`; real-time budget for the viewed ticker's near rungs, `interval=5` elsewhere; `//blp/mktlist/chain/bsym/US/<root>` for chain membership; a margin under 3,500; B-PIPE for a desk universe | quota-free chains, a larger universe | guide p33 (INTERVAL messages only, no INITPAINT), p42-44 (bsym chains never refresh; `/ticker` topics unsupported), p73 | the mktlist topic format is untested | S–M; B-PIPE L |

**1 — Window the Massive subscription.** Reuse the Bloomberg plan as it stands: centre on the book (or the last REST) spot with 5 % hysteresis, keep strikes within ±k standard deviations per expiry (the fitter's own crop), rank nearest-the-money, cap at 950 and count cumulatively; send subscribe frames of ≤ 200 like Bloomberg's batches; on "Subscription limit reached" unsubscribe the farthest and retry. Wings beyond the window come from the REST snapshot at the refit cadence (the merge already tolerates unbooked contracts: `_chain_from_book` emits them with `bid = ask = None`). With SPY's 26 expiries this is about 36 contracts per expiry — enough for the ATM / skew live layer, not for a live full-wing fit, hence 3.

**2 — Health first.** A `StreamStats` on the book (messages, last-message monotonic age, reconnects, acked / refused counts, the last vendor status text) surfaced in `feed_status` and a `GET /stream` route, plus INFO logs on connect / auth / ack / error / drop. Make `is_streaming(ticker)` true only once the ticker's contracts were acknowledged and a quote arrived; until then the ticker sits on the request path. This alone would have shown the current failure on 09-18.

**3 — Tiered rates.** The SSE hook already knows which node is on screen: subscribe its expiry (and its neighbours) on `Q.`, the rest of the universe on `AM.` bars (documented for Starter / Developer / Advanced, delayed below Advanced) or on the 15-s snapshot path. The 2026-09-02g model still holds: a calibration prices one snapshot; bars carry `quote_kind = "marks"`.

**4 — Connections.** Massive adds options connections on request ("we add them while you wait"); Business includes three. One `MassiveWebSocket` per group of ≤ 950 contracts, all feeding one `LiveBook`, is a small change (`start_streaming` holds a single `_ws` today).

**5 — A recorder / streaming service.** A separate process owns the socket(s) and appends 1-s book snapshots (contract, bid, ask, ts) to a parquet file per day; the API mounts the live book through a local channel, and the Series lens reads its frames from the recording (its `frame_asof` path already consumes store rows). It also takes the socket off the API's GIL and survives `restart.ps1`.

**6 / 7 — Day roll and silence.** Call `refresh_contracts()` from the roll, re-derive the live set, and replace the 6-s rule by "outside 09:30–16:15 ET keep the connection and expect silence; inside, N s without any message = reconnect"; report "idle" on the last message age, not on tick stamps.

**8 — Bloomberg.** The DAPI channel is healthy today (four subscriptions painted in under 8 s, SPX real-time, US equities delayed). Keep the 1-s conflation (INTERVAL messages carry the latest values only); allocate the 3,000 budget as the viewed ticker's near rungs at `interval=1` and the rest at `interval=5`; try `//blp/mktlist/chain/bsym/US/SPY` for chain membership (the guide says bsym chains do not refresh — re-subscribe at the roll) to drop the two metered listing calls; a desk-scale universe (25 tickers × full ladders) needs B-PIPE / SAPI entitlements and `//blp/apiauth` (guide p26).
